# Commerce-6 E2E — 아동의류 실상품 1개

> CTO(2026-09-26). 대상: **Bobo Choses «Terry Bermuda Shorts»(B226AC043)** —
> bobochoses.com · EUR 50 · 원산지 스페인. CEO 화면에 실제로 올라온 그 상품
> fixture 를 재사용했다(새 상품 만들지 않음).

---

## 🔴 먼저 — 실등록은 «할 수 없다». 실행해서 확인했다

```text
apps/admin/.env.local   QA_PROXY_TO_PROD · OCI_PROXY_URL   ← 둘뿐
Supabase · 네이버 · 쿠팡 · 롯데ON 자격증명   🔴 «전부 ABSENT»
QA 프록시                /api/* → 배포본(origin/main)
                         → 미푸시 39개(검증기·빌더·resolver 전부)를 «태우지 못한다»
```

그래서 프록시로 돌려도 **내 변경이 아니라 옛 코드**를 검증하게 된다.
그리고 실등록은 되돌리기 어려운 외부 행위라 승인 없이 누르지 않는다.

→ **네트워크 직전까지** 를 실제 코드로 끝까지 통과시켰다. 어댑터·빌더·검증기·
부족항목 안내는 전부 프로덕션이 쓰는 그 함수다.

---

## ① STEP 1 — 원본/공통

크롤링 직후 상태에서 비어 있는 것: 제조사 · 수입자 · KC · 품명 · 모델명 ·
중량 · 소재 · 색상 · 사용연령 · 이미지 · 상세.
재고는 `999/DEFAULT` → `resolveSourceStock` 이 **UNKNOWN** 으로 읽는다(설계대로).

## ② STEP 3~5 — 채널 통과

### 🔴 핵심 결과: **셀러가 채운 값은 하나도 사라지지 않는다**

상품정보에서 채울 수 있는 것을 전부 채운 뒤:

```text
재고 12개        → IN_STOCK qty=12   (999 에 덮이지 않는다)
쿠팡 ERROR       → 0건
롯데ON READY     → 상품명·판매가·대표이미지·상품기술서·옵션·재고 전부
```

### 롯데ON 에 남는 차단 10개는 «전부 채널 것» 이다

```text
IDENTITY_REQUIRED     거래처 정보            ← 자격증명(설정)
CATEGORY_REQUIRED     표준·전시 카테고리      ← 셀러가 고른다
NOTICE_REQUIRED       상품품목코드 · 고시 항목 ← 카테고리 선택 시 따라옴
SELLER_PLACE_REQUIRED 출고지 · 반품지 · 배송비정책 · 배송가능지역
MISSING               원산지코드             ← 89 목록에서 고른다
```

🔴 **상품정보에서 채울 수 있는데 막혀 있는 항목은 0개다.** 이것이 C-2D~F 가
닫으려던 바로 그 상태다.

### 🔴 그런데 «반복 비용» 이 드러났다

`SELLER_PLACE_REQUIRED` 4개는 C-2 에서 「저장할 곳이 없다」로 STOP 한 그 값들이다.
저장소가 없으므로 셀러는 **상품마다 이 넷을 다시 고른다.** E2E 가 그 비용을
숫자로 확인해 줬다(테스트로 고정).

## ③ 원본 재고 UNKNOWN 의 실제 거동

```text
쿠팡     등록 막지 않음 + WARNING 「원본 재고 확인」   🟢
롯데ON   READY 「재고(원본 미확인)」                  🟢
스마트스토어  아무 말 없음                            🟡 비대칭(P2)
```

## P0 / P1 / P2

```text
P0  실제 등록을 잘못 만들거나 막는 오류        🔴 «없음»
    관측된 차단은 전부 정당하다(채널 발급 코드 · 자격증명 · 카테고리)

P1  기본 셀러의 정상 등록에 필요한 누락        🔴 «없음»
    상품정보에서 채울 수 있는데 막힌 항목 0개

P2  backlog (이번에 고치지 않음)
    · 재고 UNKNOWN 일 때 payload 에 999 가 나간다 — 셀러가 정한 수가 아니다
      (C-2E 정책상 「기존 값 유지」이고 재고는 필수라 비울 수 없다.
       바꾸면 Production 등록 정책 변경이다)
    · 스마트스토어만 재고 UNKNOWN 을 알리지 않는다(쿠팡·롯데ON 은 알린다)
    · 롯데ON 평일 발송마감 "1400" — 폼 기본값, 셀러가 화면에서 보고 고친다
    · 쿠팡 `shipping` 규칙이 죽어 있다(`check: () => true`, readiness 가 걸러냄)

제외  고급 Commerce 옵션(묶음배송 · 조건부무료 · 선물) — Commerce-6 종료
```

## 수정 내용

**코드 수정 0건.** E2E 가 막히는 것을 찾지 못했다 — 찾을 것이 남아 있지
않다는 뜻이고, C-2D~F 에서 이미 닫혔다. 대신 이 상태를 **회귀 계약 9건**으로
고정했다(`commerce6-e2e-children-fashion.test.ts`).
