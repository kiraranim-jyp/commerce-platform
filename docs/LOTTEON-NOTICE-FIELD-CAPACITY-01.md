## 1. `0090` A/S 책임자와 전화번호 — 🔴 **담을 자리가 없다 (전수 확인)**

### 기존 값 존재 여부: **없다**

공통 판매자 설정은 **다섯 칸뿐**이다([seller-settings.ts](apps/admin/src/lib/seller-settings.ts)):

```
manufacturer · asContactNumber · qualityGuarantee · kcExemptionText · defaultCountryOfOrigin
```

`companyName` · `businessName` · `corporateName` · `상호` · `업체명` · `사업자명` 을
**소스 전체에서 검색해 0건**이다. 채널별 프로필에도 없다:

| 후보 | 실제 의미 | 쓸 수 있나 |
|---|---|---|
| `SellerProfile.name` | 배송 «프로필» 이름(예: 기본 프로필) | ❌ 업체명이 아니다 |
| `SellerProfile.returnChargeName` | 반품 «주소지» 라벨(값: "반품주소지") | ❌ |
| `commonSellerSettings.manufacturer` | 제조사 | ❌ A/S 주체와 다르다 |
| `asContactNumber` | A/S 연락처(번호) | 🟡 절반 — 번호만 |

배선은 이미 있다 — `build-context.ts:250` 에 **`sellerAsCompanyName: null` 이 하드코딩**돼
있고, 바로 위 주석이 「A/S «업체명» 칸은 아직 없다(DB 변경은 CPO STOP 중)」라고 적고 있다.

### 필요한 정확한 저장 의미

```
「A/S 를 책임지는 «업체의 이름»」
  · 판매자명도, 제조사명도, 배송 프로필명도 «아니다»
  · 고시는 업체명과 전화번호를 «모두» 요구한다 → 번호만으로는 못 채운다
  · 값의 성격: 워크스페이스 단위로 «한 번» 정하면 모든 상품·모든 채널에 같다
```

→ 🔴 **CPO 결정 필요.** CTO 소견으로는 **COMMON SELLER SETTING** 이다 —
상품마다 다르지 않고 채널마다 다르지도 않다. 이미 `asContactNumber` 가 그 자리에
있으므로 짝이 되는 칸이 같은 자리에 있는 것이 자연스럽다.

## 2. `0220` 동일모델의 출시년월 — 🔴 **소스가 없다**

### 필요한 정확한 저장 의미

## 3. `1830` 크기ㆍ체중의 한계 — 🟡 **필수인데 조건부다**

공식 표에서 직접 확인:

```
필수여부        Y  (13행 전부 Y)
작성 가이드라인  「착용 또는 탑승용 어린이제품과 같이 크기ㆍ체중에 제한이 있는
                 품목의 경우 반드시 기재해주세요.」
```

🔴 **이 둘이 서로 당긴다.** 필수(Y)인데 가이드라인은 「제한이 있는 품목의 경우」라는
조건문이다. 그래서 질문이 생긴다 — **제한이 없는 상품(일반 아동의류)은 무엇을 적나.**

```
확인된 것      필수여부 Y · 가이드라인 원문 (위)
확인 못 한 것  「해당 없을 때」의 기재 기준 — 이 문서에서 찾지 못했다
```

🔴 자동으로 `해당없음` · `N/A` · 공란을 넣지 «않았다». 그 셋은 서로 다른 결과를
낳을 수 있고(항목 누락 vs 문자열), 어느 쪽인지 모른다.

→ **외부 확인 항목.** 롯데ON 에 물을 문장: 「품목 23 의 항목코드 1830 은 필수(Y)로
표기돼 있는데, 크기·체중 제한이 없는 상품은 `pdArtlCnts` 에 무엇을 기재해야 합니까?
항목 자체를 `pdItmsArtlLst` 에서 생략해도 됩니까?」
