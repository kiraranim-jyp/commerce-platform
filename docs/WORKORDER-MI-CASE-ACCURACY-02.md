## 1. 목적

> **MI 가 예상 총 원가를 산출하고, 그것으로 권장 판매가격을 계산한 뒤,
> 국내 동일상품 비교가격과 대조해 판매 경쟁력을 판단한다.**

둘을 한 번에 확인한다 — ① 실제 상품 데이터에서 CASE 판단이 정확한가
② **관세·수입 부가세를 MI 가 «먼저» 산출해 제공하고 판매자가 수정하는** 원가 구조가 가능한가.

🔴🔴 **이번 지시서의 핵심 정책 변경** — 관세·부가세는 **판매자 입력 항목이 아니다.**
**MI 선산출 → 판매자 수정 → 총원가·권장가·CASE 재계산** 이다.
🔴 **판매자가 처음부터 직접 입력해야만 분석되는 구조는 금지.**

## 2. 🟢 재조사 금지 — 이미 확정된 사실

| 항목 | 확정 내용 |
|---|---|
| CASE owner | `packages/pricing/src/price-recommendation.ts` → `computePriceRecommendation`(:120) |
| CASE 원가 입력 | `market-intelligence.ts:958` 이 넘기는 **`cost.landedCostKrw`** |
| 현재 착지원가 | `packages/pricing/src/breakdown.ts:70` — **`landedCostKrw = costKrw + shippingKrw`** |
| 수수료 처리 | `netProfitAt = priceKrw − landedCost − platformFeeKrwAt(priceKrw, fee)` · 🟢 **이중 차감 없음** |
| CASE D 조건 | `domesticBasis !== "EXACT"` **또는** `domesticLowestPriceKrw == null` |
| CASE C 조건 | `netProfitAt(marketPrice) <= 0` ⟹ 🟢 **추천가 `null`**(억지 추천 0) |
| 환율 추정 | `isRateEstimate` 면 **추천을 아예 만들지 않는다**(market-intelligence:956) |
| 🔴 관세·수입 부가세 | **CASE 원가 경로에 반영 «경로 자체가» 없다** |
| 🔴 기타 비용 | `miscCostKrw` 는 `computeLandedCost` 의 `totalCostKrw` 에만 있고 **CASE 에 쓰이지 않는다** |

🔴 **CTO 의 과거 「② 조건부(miscCostKrw 로 수용 가능)」 보고는 정정됐다** — ③ **미반영(경로 부재)** 이다.
🔴 **표현 규칙** — 「모든 상품이 CASE D」로 적지 않는다. 정확히는
**「확인된 국내 가격 데이터에서는 D 조건이 우선 적용되어 A/B/C 를 실측할 수 없다」**.
🔴 그리고 **「거짓 추천을 막는다」 ≠ 「정확하다」** — 섞지 않는다.

## 3. 실행 범위 A — 상품별 CASE 정확도

🟢 **기존 GT fixture·산출물 재사용** · 🔴 새 후보 수집·데이터 구축 **금지**.

### A-1 GT 입력 확보 (값 없으면 `NULL / 미확보` — 🔴 임의로 채우지 않는다)
`landedCostKrw`(또는 실제 전달값) · `domesticBasis` · `domesticLowestPriceKrw` ·
`brandMedianPriceKrw` · `expectedFeePercent` · `minimumMarginPercent` · `targetMarginPercent`

🟡 출처 후보 — `apps/admin/src/app/pipeline/commerce/__tests__/product-tab-composition.ts`
(`CASE_D_FACTS` 계열) · 기존 GT fixture · `docs/MI-KIDS-TRIAGE-V2.json`(🔴 **읽기 전용** ·
그 하니스는 `writeFileSync` 로 덮어쓰므로 **돌리지 않는다** · 해시 `1408034e…f1c37`)

### A-2 순수 함수 측정
확보한 **실제 GT 입력** 을 `computePriceRecommendation` 에 직접 넘긴다.
🟢 환율 HTTP 불필요 · 🔴 Production DB 접근 금지.

### A-3 상품별 결과표
상품 식별값 · GT 정답(SAME/DIFFERENT/SIMILAR) · 국내 비교 근거(EXACT/그 외/미확보) ·
총원가 · 수수료율 · 권장 최저가 · 목표가 · **CASE(A/B/C/D)** · GT 일치(일치/불일치/측정불가) · 오류 원인
🔴 **GT 정답과 CASE 판단은 서로 다른 평가 항목** 이다 — 혼동하지 않는다.

### A-4 A/B/C/D 분기 검증
🔴🔴 **실제 GT 측정(4-A)과 합성 입력 분기 검증(4-B)을 «분리해» 보고한다.**
경계값 · 수수료 반영 · 순이익 0 경계 · 국내 비교가 부재를 확인한다.
🔴 로직 변경·threshold 완화 **금지** · 도달 못 한 CASE 는 **미측정** 으로 표시.

### A-5 전체 회귀 + 최소 수정안
기존 회귀 명령 재사용(CASE·가격 계산·SAME·국내외 비교).
🔴 **기존 실패와 신규 실패를 구분** 한다. 🔴 수정이 필요해 보여도 **코드를 바꾸지 않고**
재현 조건 · 영향 범위 · 최소 수정안만 제안한다.

## 4. 실행 범위 B — 관세·수입 부가세 산출 구조 **조사**

### B-1 확정된 제품 방향
```
① MI 가 예상 관세 산출 → ② MI 가 예상 수입 부가세 산출 → ③ 기본값을 판매자에게 «먼저» 보여줌
→ ④ 판매자가 필요시 수정 → ⑤ 총 원가 재계산 → ⑥ 권장 판매가격·CASE 재계산
```

### B-2 조사 항목
원산지·수출국 · 상품가격·통화 · 배송비/과세가격 산정 데이터 ·
**카테고리·HS 코드 등 품목 분류 보유 여부** · 관세율 확인 가능한 기존 데이터/서비스 ·
수입 부가세 과세표준 · **관세·부가세 산출 «순서»와 계산 기준** ·
기본 산출값 신뢰도와 미확보 처리 · 판매자 수정값 저장·재계산 연결 가능성

### B-3 🔴 반드시 네 등급으로 구분
**자동 산출 가능** / **추가 정보 필요** / **외부 기준 확인 필요** / **산출 불가**
🔴 확인되지 않은 세율·과세 기준을 **임의로 만들지 않는다.**
🔴 산출 불가를 **0원으로 처리하지 않는다** — 미확보/산출불가를 표시하고 기본값 제공 정책을 **제안** 한다.

### B-4 연결 확인
```
해외 상품가격 + 국제배송비 + 관세 + 수입 부가세 + 국내배송비 + 기타비용
→ 예상 총 원가 → 수수료·목표마진 반영 → 권장 판매가격
→ 국내 동일상품 비교가격 대조 → MI 최종 판매 경쟁력 판단
```
🔴 국내 동일상품 비교가가 없거나 동일성 근거가 불충분하면 **경쟁력 판단을 확정하지 않는다.**

### B-5 제안 산출물
재사용 가능한 코드·데이터 · 추가 필요 데이터 · 산출 방식 · 판매자 수정값 처리 ·
총원가/CASE 재계산 연결 지점 · 신뢰도 및 산출불가 처리 · **최소 구현 범위와 예상 변경 파일** ·
구현 전 필요한 정책/외부 기준 확인 사항
