## 1. 🔴🔴 방법 — Human GT 대신 **CONTROL probe**

CTO 는 라벨을 만들 수 없다. 그래서 사람 판단 대신 **사이트가 스스로 내는 반증** 을 썼다.

```
같은 호스트에 **존재할 수 없는 상품 URL** 을 넣는다.
  bogus → 404/410 또는 리다이렉트  ⟹ 없는 상품을 «정직하게» 알린다
  bogus → 200 + 본문               ⟹ 🔴 그 호스트에 **200 soft-404 «능력»** 이 있다
```

### 🔴🔴 1차 CONTROL 이 무효였고 내가 그것을 잡았다

```
1차: 경로 **마지막 칸** 을 bogus 로 바꿨다 → 200 이 **5건** 나왔다
🔴 그런데 한국 Cafe24 계열은 마지막이 `…/category/367/display/1/` 같은 **꼬리표** 다.
   바꿔도 **같은 상품** 이 온다 — biskuit·littleluna 는 bogus 제목이 후보 제목과
   **글자 그대로 같았다**(그것이 무효의 증거다).
2차: 경로의 **숫자 세그먼트**(= 상품번호)를 바꿨다
   biskuit **404** · miniboutique **404** · mustit **404**  ← 전부 뒤집혔다
🔴 **1차의 「200 5건」을 그대로 보고했으면 틀렸다.** 확정값은 **2건** 이다.
```

🔴 무효 판정 기준을 코드에 박았다 — **bogus 제목이 그 호스트의 실제 후보 제목과 같으면
그 CONTROL 은 무효** 다(없는 상품이 아니라 같은 상품을 받은 것이다).
