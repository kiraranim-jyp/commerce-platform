# WU-034 — `BRAND_UNCONFIRMED` 독립 증거원 전수 분해

> 🔴 **측정 전용.** 운영 코드 변경 **0** · HTTP **0**(WU-032 캐시) · AI **0** · 비용 **₩0** ·
> 구현 **0**. CPO 금지 유지 — 브랜드 추정 로직 0 · 도메인→브랜드 매핑 **구현 0**.

CPO 지시: 「`BRAND_UNCONFIRMED` 를 독립 증거원별로 전수 분해해서 **실제로 안전하게
확인 가능한 증거원이 존재하는가** 를 검증한다. **브랜드를 «추정» 하는 것과 «확인» 하는
것을 절대 섞지 않는다.」**

---

## 0. 🔴 먼저 숫자를 정정한다

CPO 보고서의 「`BRAND_UNCONFIRMED` 13건」은 WU-033 §2 의 **「blocker 가 막는다 13/14」**
가 옮겨진 것이다. 실제 분해는 이렇다:

```
MISS 14
 ├─ **BRAND_UNCONFIRMED   9**     ← 이 WU 의 대상
 ├─ 그 외 blocker          4      (NO_TITLE_OVERLAP 단독 1 · BRAND_MISMATCH 1 ·
 │                                 MATERIAL 1 · SIZE_SYSTEM 1)
 └─ blocker 없음(축 부족)   1
```

🔴 다음 WU 범위가 이 숫자 위에 서므로 **9 로 고정한다.**

### 9건은 «어느 쪽» 이 비었나 — 깨끗하게 갈린다

```
🔴 원상품 브랜드 없음   **4**   (전부 S6 · origin = bobochoses.co.jp)
🔴 후보 브랜드 없음     **5**
   둘 다 없음            0
   둘 다 있는데 UNCONFIRMED  **0**   ← 「확인 로직이 까다로워서」가 아니다. 값이 없다
```

## 1. 🔴🔴 후보 쪽 5건 — **확인 등급 증거원이 0 건이다**

등급을 섞지 않고 셌다(CPO 요구):

| 증거원 | 등급 | 5건 중 보유 |
|---|---|---|
| JSON-LD `Product.brand` | 🟢 확인 | **2** — 🔴 그런데 값이 **`SS26`** |
| `og:brand` | 🟢 확인 | **0** |
| `product:brand` | 🟢 확인 | **0** |
| microdata `itemprop="brand"` | 🟢 확인 | **0** |
| `og:site_name` | 🔴 **추정** | 2 (`"BOBO CHOSES Japan official site"`) |

```
donokids.com ×2 · beaumonde.co.kr ×1  →  🔴 **어떤 소스도 없다**
bobochoses.co.jp ×2                  →  🔴 JSON-LD brand = **"SS26"**
```

🔴🔴 **`SS26` 은 브랜드가 아니라 시즌코드다.** 헌장에 이미 기록된 `AW26` 과 **같은 결함**
이고, 🟢 **우리 `brand-resolver.ts` 의 SEASON_CODE 규칙이 그것을 올바르게 거부하고 있다.**
즉 후보 브랜드가 null 인 것은 **버그가 아니라 정상 동작** 이다.

🟢 **그러므로 후보 쪽 「안전하게 확인 가능한 증거원」 = 0 이다.** 남는 것은 `og:site_name`
뿐이고 그것은 **추정 등급** 이며 WU-009 가 반증했다(원본 도메인 25/26 이 멀티브랜드 리테일러).

---

## 2. 🔴🔴 원상품 쪽 4건 — 같은 사이트의 **같은 결함**이다

S6 의 origin 이 `bobochoses.co.jp` 이고, 위 후보 2건도 같은 사이트다.
**그 사이트가 brand 칸에 시즌코드를 적는다** → resolver 가 거부 → null.

🟢🟢 **그래서 9건 중 6건(원상품 4 + 후보 2)이 «한 사이트의 데이터 관행» 하나로 설명된다.**

---

## 3. 🔴🔴🔴 그 공백을 메우면 — **1 을 벌고 «거짓 불일치» 3 을 만든다**

도메인→브랜드 주입(= CPO 금지 항목)을 **구현하지 않고 효과만** 쟀다.
🔴 WU-032 는 「SAME 이 몇 개 늘었나」만 셌다. 이번엔 **blocker 전이**를 봤다 —
`BRAND_UNCONFIRMED`(모름)가 `BRAND_MISMATCH`(다름)로 바뀌면 **신호가 나빠지기** 때문이다.

```
주입이 닿는 행            7
🟢 UNCONFIRMED 해소        6
🔴🔴 UNCONFIRMED → **MISMATCH**   **3**
🟢 verdict 개선            **1**   (bobochoses.com → SAME)
🟢 verdict 악화            0
🟢 False SAME              0
```

### 🔴 MISMATCH 로 바뀐 3건의 정체 — **전부 실제로는 같은 브랜드다**

| 후보 도메인 | 후보 brand 칸 값 | 주입 후 |
|---|---|---|
| kihanan.com | `BOBOCHOSES ボボショーズ` | 🔴 BRAND_MISMATCH — **일본어 병기** |
| m.web.mustit.co.kr | `보보쇼즈` | 🔴 BRAND_MISMATCH — **한글 음차** |
| biskuit.kr | `비스킷` | 🔴 BRAND_MISMATCH — **샵 이름이 브랜드 칸에 들어갔다** |

🔴🔴 **즉 후보의 브랜드 칸 자체가 이미 오염돼 있다.** 원상품 브랜드를 채우는 순간 그
오염이 **「모름」에서 「다름」으로 승격** 된다 — 더 강한 부정 신호다.

🔴 그리고 안전 마진도 줄었다 — GT **DIFFERENT** 2건(tinyapple · ladida)에서
`BRAND_UNCONFIRMED` 가 **사라졌다**. 이번 표본에서는 False SAME 0 을 유지했지만,
**그 2건을 막고 있던 blocker 가 없어진 것은 사실** 이다.

## 5. 🟢 그 대신 **진짜 원인 둘**이 이름을 얻었다

```
① 🔴 후보 **브랜드 칸 오염** — 샵 이름(`비스킷`)이 브랜드로 들어간다
     → 브랜드 축을 쓰려면 **먼저 이 칸을 신뢰할 수 있어야** 한다

     🔴 그런데 그 수단은 **별칭 사전** 이고 Registry 성격이다(§12-0 과 만난다)
```

🔴🔴 **②가 이 트랙에서 처음 드러난 구조적 사실이다** — 「국내 샵은 브랜드를 한글로
적는다」. 그래서 **영문 브랜드 문자열 비교로는 국내 후보의 브랜드를 영원히 확인할 수 없다.**
