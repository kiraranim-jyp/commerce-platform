## A. 쿠팡 — 공식 문서로 확인

출처: 쿠팡 Developer Center, Product Creation API(공개).

| 질문 | 답 | 근거 |
|---|---|---|
| A-1. KC 면제 문구가 **셀러 확인을 요구**하는가 | **아니오** | 쿠팡에는 확인(confirmation) 개념 자체가 없다. 우리 모달은 우리가 만든 것이다 |
| A-2. 현재 기본 문구가 **공식 허용 default** 인가 | 🔴 **아니다** | 공식 문서에 기본값·placeholder 정의가 **없음**. 그 문구는 «우리 것» 이다 |
| A-3. KC 관련 **공식 필드/required rule** 이 있는가 | 🔴 **있다 — 그런데 우리가 안 쓴다** | `items[].certifications` (`certificationType`·`certificationCode`·`certificationAttachments`, **선택**). 우리 코드 참조 **0건** |
| A-4. 기본 문구가 «적합성 판단» 인가 «단순 payload» 인가 | 🔴 **소비자에게 보이는 고시 문구** | `notices[].content` 로 나간다. `noticeCategoryName`·`content` 는 필수 |
| A-5. 아동의류 별도 조건 | **문서에서 못 찾음** | 확인 못 함 |

### 🟢 그런데 구매대행은 «공식 기전으로 이미» 선언하고 있습니다

```ts
// coupang/build-payload.ts:223~228 (공식 문서 근거 주석 포함)
deliveryMethod: "AGENT_BUY"   // 해외 구매대행
pccNeeded: boolean            // 공식 문서: AGENT_BUY 면 true 여야 한다
```

→ **구매대행 「선언」은 이미 올바른 자리에서 하고 있습니다.**
그렇다면 고시 문구의 「구매대행」 부분은 **중복**이고, 남는 것은
「**KC마크 없이 … 가능**」이라는 **검증되지 않은 주장** 한 조각입니다.

## B. 스마트스토어 — 실측/공식으로 고정

| 항목 | 확인 내용 | 근거 |
|---|---|---|
| B-1. `OVERSEAS` 의 의미 | 「구매대행」 면제 사유. **셀러가 라디오로 고른다** | `PlatformPreview.tsx:342` |
| B-2. 인증번호가 필요한 조건 | 카테고리 `exceptionalCategories` 에 `CHILD_CERTIFICATION` 이 있고, 셀러가 「대상 아님」을 고르지 않았을 때 | **채널 메타데이터가 준 사실** — 우리 추측 아님 |
| B-3. confirmation 게이트 | `confirmed && policyVersion 일치 && categoryCode 일치` 아니면 FAILED | `register/route.ts:421` |
| B-4. payload 매핑 | `certificationTargetExcludeContent.{childCertifiedProductExclusionYn, kcCertifiedProductExclusionYn, kcExemptionType}` · 조합이 유효하지 않으면 **키 자체를 만들지 않음** | `kc-declaration.ts:92` |

### 🟢 이 모듈은 «판정하지 않는» 설계입니다 (원문)

> 「이 모듈은 판매자가 «고른 것» 을 네이버 필드로 옮겨 적기만 한다. 어떤 상품이
>  KC 대상인지, 면제인지는 **법적 판단이고 따져가 내리지 않는다.** 그래서 입력이
>  없으면 `undefined` 를 내고, **억지로 기본값을 만들지 않는다.**」

그리고 왜 그렇게 됐는지도 적혀 있습니다 —

> 「실제 인증서가 없는 판매자는 빠져나갈 길이 없었고 — 결국 아무 값이나 넣었다.
>  「12313ㄹㅇ」이 실제 어린이제품에 붙은 뿌리가 여기다.
>  **출구가 없으면 시스템은 거짓말을 보상한다.**」

🔴 **쿠팡과 정확히 반대 방향의 해법입니다.** 스마트스토어는 «출구를 만들어»
풀었고, 쿠팡은 «기본값을 채워» 풀었습니다.

## D. 🟢 정책 충돌이 «증거로» 풀렸습니다

KC-01 에서 「세 채널이 다른 말을 한다」고 보고했는데, 두 채널의 근거를 찾았습니다.

| 출처 | 어린이제품 + 구매대행 | 근거의 성격 |
|---|---|---|
| **스마트스토어** | **제공하지 않는다** | 🟢 **실측**(N-3.66, CEO 승인 2026-08-20) — 어린이제품 인증 3종(1040/1041/1042)의 `kindTypes` 가 전부 `["ETC","CHILD_CERTIFICATION","KC_CERTIFICATION"]` 뿐, **`OVERSEAS` 는 생활용품/전기용품류에만** 있다. 원문: 「구조적 확인, 추측 아님」 |
| **롯데ON** | **선택할 수 없다** | 🟢 **공식 문서**(품목표 `23 0200` 가이드라인) |
| **쿠팡** | 「**구매대행 가능**」이라고 **우리가** 적는다 | 🔴 채널이 아니라 **우리 기본값** |

🔴 **서로 독립적인 두 채널이 같은 방향을 말합니다.** 반대 방향인 것은 쿠팡
«채널» 이 아니라 **우리 코드의 기본 문구** 하나입니다.

🔴 **그래도 저는 법적 판단을 하지 않습니다.** 네이버의 사실은 「그 API 가 그
선택지를 주지 않는다」는 **구조적 사실**이고, 롯데ON 의 것은 **작성 가이드라인**
문장입니다. 둘 다 「법적으로 면제가 불가능하다」와 같은 문장은 아닙니다.
**정책 근거와 현재 구현을 분리해 그대로 올립니다.**

## E. 🔴 조사 중 새로 찾은 빈틈 (스마트스토어)

```ts
// naver/kc-declaration.ts:58  validateKcDeclaration()
if (capability.childCertificationRequired && d.child === undefined) → CHILD_CHOICE_MISSING
if (d.kc === "EXEMPTION" && d.exemptionReason === undefined)        → KC_EXEMPTION_REASON_MISSING
if (d.kc !== "EXEMPTION" && d.exemptionReason !== undefined)        → KC_EXEMPTION_REASON_NOT_ALLOWED
```

**「어린이제품 카테고리인데 면제 사유 = `OVERSEAS`(구매대행)」를 막는 검사가
없습니다.** 조합의 «완결성» 만 보고 «허용 여부» 는 보지 않습니다.

그런데 §D 의 실측은 **네이버가 어린이제품에 `OVERSEAS` 를 제공하지 않는다**고
합니다. 즉 셀러가 우리 화면에서 그 조합을 고를 수 있습니다.

🔴 **고치지 않았습니다**(KC-02 는 조사입니다). 다만 이것은 §D 의 정책 충돌이
**우리 화면에서 실제로 만들어질 수 있는 경로**라 별도로 보고합니다.

## F. 최종 산출물 — **`PARTIAL_COMMON_KC`**

### 🟢 Common 으로 올릴 수 있는 것 — **판매자 «확인 행위» 하나**

```
confirmed · confirmedAt · policyVersion · categoryCode · platform
```

- 이미 구조가 있고(`seller_compliance_confirmations`), **정책버전·카테고리로
  무효화되는 규칙까지 돌고 있습니다**.
- `platform` 이 이미 컬럼이라 **스키마 변경 없이** 다른 채널을 담을 수 있습니다.
- 🔴 다만 **스마트스토어 동작을 바꾸지 않고** 「일반화」만 해야 합니다.
- 🔴 그리고 CPO 확정대로 — **`DEFAULT` 를 자동으로 `CONFIRMED` 로 간주하지
  않습니다.** 쿠팡의 기본 문구가 확인으로 승격되면 안 됩니다.

### 🔴 Common 으로 올릴 수 «없는» 것

| 대상 | 이유 |
|---|---|
| KC 대상 판정 | 근거가 채널마다 다르다 — 네이버 카테고리 메타 / 롯데ON 품목코드 / 쿠팡 없음 |
| 면제 사유 | §D 의 충돌. 채널이 제공하는 선택지 자체가 다르다 |
| 인증 payload 모양 | 네이버 3필드 선언 / 롯데ON 구조체(유형+번호) / 쿠팡 `certifications` 미사용 |
| 「인증번호를 만들지 않는다」 | 🟢 이미 3채널 공통이지만 **필드가 아니라 원칙**이다 — 합칠 대상이 아니다 |
