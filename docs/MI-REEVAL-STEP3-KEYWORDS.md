## 0. 🔴 CPO 금지를 **코드로** 지켰다

```
❌ 문자열 완전 일치(`=`) 비교        🟢 축별 키워드 추출 → 정규화 → «의미» 비교
❌ 한쪽에만 있으면 MISMATCH          🟢 **UNKNOWN** 이다 — 계약이 전수로 단언한다
❌ 키워드 일치율 → 동일성 «확률»      🟢 산출에 `matchRate`·`similarity`·`score`·
                                       `confidence`·`probability` 칸이 **0** 이다(계약)
❌ 키워드 수로 SAME 결정             🟢 최종 판정 칸이 **아예 없다**(`shadowVerdict` 0 · 계약)
❌ 근거 없는 브랜드 동의어            🟢 **운영 `brand-alias.ts` 의 한국어 alias 그 넷** 만
```

🔴 동의어 근거를 **등급으로** 보존했다 — `IDENTICAL` / `NORMALIZED` / `REGISTRY`(운영 등록부 근거) /
`OBSERVED`(이 코퍼스 관측) / `NONE`. **섞지 않는다.**
🔴 `brand-alias.ts` 를 **import 하지 않았다** — Shadow 가 운영 등록부에 의존하면 그 파일을 고칠 때
Shadow 결과가 **조용히** 바뀐다. 🟢 값을 베끼고 출처를 적었다.

## 5. 🔴 내가 틀린 것 — **이번에 하나, 보고 전에 잡았다**

```
🔴🔴 「브랜드 다국어 연결이 발화한 쌍 **17**」 — **거짓이었다.**
   `synonymBasis` 에 `REGISTRY` 가 있으면 다 세었고, 영문 구조화 brand(`Bobo Choses`)까지
   `REGISTRY` 로 찍혀 들어왔다(등록부에 **있기만 하면** 그 라벨을 줬다).
🟢 문자체계로 다시 쟀다 — **한글↔영문이 «실제로» 이어진 쌍은 2** 이고,
   한글 브랜드 표기가 추출된 쌍 자체가 **원본 0 · 후보 3** 이다.
🟢 비교기를 고쳤다 — 영문 그대로면 `IDENTICAL` 이고 `REGISTRY` 는 **브리지일 때만** 쓴다.
🟢 계약으로 잠갔다 — 영문 raw 가 `REGISTRY` 로 찍히면 **FAIL** 한다.
🔴 그대로 보고했으면 「다국어 처리가 잘 돈다(17쌍)」는 **8배 과장** 이었다.
```
