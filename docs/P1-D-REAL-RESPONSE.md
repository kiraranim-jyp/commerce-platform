### 🔴 발견 1 — 출고지와 반품지의 «번호가 같다»

`PLO3837441` 하나가 `typeCode` 만 달리해 두 번 나온다. **번호만으로는 구분되지
않는다** — `(no, typeCode)` 쌍이 식별자다.

우리 저장소는 `outbound_place_no` / `return_place_no` 를 따로 두고 payload 도
`owhpNo` / `rtrpNo` 로 나눠 보내므로 **자리로 구분된다 — 현 구조는 맞다.**
🔴 그러나 내 테스트 fixture 는 `PLO3837441` / `PLO3837441_R` 로 **서로 다른 번호**를
썼다. 현실에 없는 모양이었다.

### 🔴 발견 2 — `dvpTypCd` · `rprtYn` 이 «진짜로» 온다

`c14d676` 이 「IP allowlist(403)로 실호출 검증 불가」라 적어 둔 그 두 필드가
**실응답에 있고 값도 정확하다**(02/01 · isDefault=true).

→ **P1-1(출고지 자동 해결)의 근거가 「문서」에서 「실응답」으로 올라갔다.**

### 🔴 발견 3 — 「선택 안 함」의 진짜 원인이 확정됐다

```
후보 1건 + isDefault=true  →  autopick 이 채운다  →  CEO 화면에서 출고지·반품지가 «차 있었다»
```

설정에서 온 값이 아니었다. **S-24 에서 fixture 를 후보 2건으로 바꿔 두 경로를
가른 판단이 옳았다.**

### 🔴 발견 4 — 이름 안에 번호와 «주소 전체» 가 들어 있다

```
"PLO3837441_출고지__Am Holzweg 28-34|ACI, PG110174 Kriftel|Hessen"
 └ 번호 ┘ └유형┘ └──────────── 주소 ────────────┘
```

우리가 코드를 붙인 게 아니다. 채널이 그렇게 부른다. **자르지 않는다**(판매자센터
이름과 달라진다). 다만 셀러 화면에 이대로 세우는 것이 맞는지는 **표시 설계**의
