# P0-CHANNEL-03 F-13 — SmartStore 수정 가능 범위

> CEO 지시 §6(2026-09-26). **조사 결과 문서이며, 정책을 새로 정한 것이 아니다.**
> 코드·payload 를 읽어 「무엇이 수정되는가」를 있는 그대로 적는다.

## 세 가지를 구분한다

| | 뜻 |
|---|---|
| **UI 수정** | 셀러가 화면에서 값을 바꿀 수 있는가 |
| **UPDATE 반영** | 그 값이 수정 payload 에 실려 SmartStore 로 나가는가 |
| **변경 감지** | 우리가 「바뀌었다」를 **대조해서 확인**할 수 있는가 |

🔴 **셋은 다른 질문이다.** 특히 「UPDATE 반영 ○ · 변경 감지 ✗」인 축이 있다 —
값은 나가지만 우리가 바뀐 줄 모르는 것이고, 대표이미지가 그렇다.

## 표

| 항목 | UI 수정 | UPDATE 반영 | 변경 감지 | 검증 |
|---|:---:|:---:|:---:|:---:|
| 판매가격 | ○ | ○ | ○ | 🟢 **Production PASS** |
| 상품명 | ○ | ○ | ○ | 🟡 |
| 재고수량 | ○ | ○ | ○ | 🟡 |
| 상세설명 | ○ | ○ | ○ | 🟡 |
| 모델명·제조사·브랜드 | ○ | ○ | ○ | 🟡 |
| 원산지(코드) | ○ | ○ | ○ | 🟡 |
| KC 대상제외 신고 | ○ | ○ | ○ | 🟡 |
| 대표이미지 | ○ | ○ | **✗** | 🟡 |
| 추가이미지 | ○ | ○ | △ 개수만 | 🟡 |
| 옵션 | ○ | ○ | △ 개수만 | 🟡 |
| 상품정보제공고시 | ○ | ○ | △ 존재만 | 🟡 |
| 배송/반품 정책 | ○ | ○ | **✗** | 🟡 |
| 카테고리 | ○ | **✗** | ○ | 🔴 UPDATE 불가 → 재등록 |

### 왜 「변경 감지 ✗」인가

- **대표이미지 · 추가이미지** — 등록할 때마다 네이버에 **재업로드**돼 URL 이 항상
  새 것이다. 대조하면 아무것도 안 고쳐도 매번 「바뀜」이 된다. 그래서 개수만 본다.
  🔴 값은 **나간다** — 이미지를 바꾸면 반영된다. 우리가 그 사실을 미리 말하지
  못할 뿐이다.
- **배송/반품 정책** — 서버가 정규화한다(`deliveryBundleGroupId` 를 null 로
  보내면 기본 그룹 ID 가 채워져 돌아온다). 대조하면 항상 다르다.
- **카테고리** — 읽고 대조는 되지만, SmartStore 가 **수정을 지원하는지 확인된 바
  없어** capability 가 `UNKNOWN` 이다. 변경 시 UPDATE 가 아니라 재등록(RECREATE)
  으로 간다. 🔴 「존재 확인」과 「수정 가능」은 다르다.

### 결과적으로

**대조 못 하는 축이 남아 있는 한 「변경 없음(NOOP)」은 나오지 않는다.** 수정을
보내면 화면의 내용으로 전체가 다시 등록된다 — 그것이 안전한 쪽이다. 감지하지
못한 변경이 조용히 사라지는 것보다 낫다.

## 대표이미지가 상세설명에 안 보이는 건 (§4)

**분기 A** — `images.representativeImage` 에는 있고 `detailContent` 에는 없다.
그리고 이것은 **버그가 아니라 기본값**이다:

```ts
// apps/admin/src/app/api/pipeline/canonical-product.ts
useInDescription: !item.isRepresentative,
```

```
// packages/shared/src/product-types.ts
대표 이미지는 기본 false(설명에서 또 반복해서 보여줄 필요가 적음)로 시작한다
```

`detailContent` 는 `product.images` 중 `useInDescription` 이 켜진 것만 넣는다.

### 🔴 이미 켤 수 있다 — 코드 변경 없이

「상품 이미지」 화면의 각 이미지 카드에 **`상세페이지 사용 / 미사용`** 토글이
있고, 대표이미지도 켤 수 있다(`ImageCard.tsx` · `toggleImageUsage`). 켜면 그
다음 등록·수정부터 상세설명 HTML 에 들어간다.

### 자동 삽입하지 않았다

CEO 지시(§4-D·§5)대로 **임의로 넣지 않는다.** 대표이미지와 상세설명 콘텐츠는
역할이 다르고, 합치면 Master 의 이미지 구조가 무너진다:

```
Master                      SmartStore
 ├─ 대표이미지        →      representativeImage
 ├─ 추가이미지        →      optionalImages
 └─ 상세설명 HTML     →      detailContent
```

**기본값을 바꿀지는 정책 결정이다.** 바꾸려면 위 한 줄(`!item.isRepresentative`)
을 `true` 로 두면 되고, 그 순간 **모든 신규 수집 상품**의 상세설명에 대표이미지가
한 장 더 들어간다 — 그래서 CEO 확인 없이 바꾸지 않았다.
