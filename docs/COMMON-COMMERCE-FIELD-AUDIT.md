## 0. 결론 셋 — 먼저

### ① 롯데ON 화면이 비어 있던 «직접» 원인은 1줄짜리 결함이다

```
route.ts:140                     export async function GET()   ← 핸들러는 이것뿐
LotteOnRegistrationPanel:755     fetch(".../delivery-settings")         GET  ✅
LotteOnDeliveryMapping:185       fetch(".../delivery-settings", POST)   405  ❌
```

405 → 목록 0 → 고를 수 없음 → `lotteon_seller_settings` 빈 채 → 「선택 안 함」.
**「롯데ON 연결」 화면은 한 번도 동작한 적이 없다.**

전수 대조(호출 93 × 라우트 95, 주석 제거): **불일치 이 1건뿐.**

### ② 🔴 「자동 변환 불가」는 질문이 틀렸다 — 변환이 아니라 «채널에 묻는 것» 이다

조사 초안은 출고지를 이렇게 적었다 — *「공통은 쿠팡 Wing 코드, payload 는 롯데ON
번호 → 코드체계가 달라 자동 변환 불가」*. **그 문장이 이 스프린트 10시간을
「셀러에게 고르게 하는 화면」 쪽으로 끌고 갔다.**

스마트스토어는 같은 문제를 **변환 없이** 푼다.

```
naver/_lib/resolve-context.ts:114
  addressBooks.find(a => a.addressType === "RELEASE")?.addressBookNo
  → 채널에게 목록을 받아 «유형» 으로 고른다. 셀러 설정 0 · 매핑 화면 0
```

그리고 **롯데ON 150 도 같은 재료를 이미 준다.**

```
route.ts:190   typeCode: str(row,"dvpTypCd")      02 = 출고지 · 01 = 반품지
route.ts:194   isDefault: str(row,"rprtYn")==="Y"  대표 출고/회수지 여부
```

쿠팡 코드를 롯데ON 코드로 바꾸는 것은 확실히 불가능하다. 그러나 **그럴 필요가
없다** — 롯데ON 에게 물어서 유형으로 고르면 된다. 실제로 이미 autopick 이 있고,
CEO 캡처에서 출고지·반품지가 채워진 것이 그 증거다(설정이 아니라 autopick).

### ③ 「이름만 보여준다」가 롯데ON 에서는 코드를 못 가린다

```
route.ts:189   name: str(row,"dvpNm")       ← 채널이 주는 이름 그대로
실제(캡처)     "PLO3837441_출고지__Am Holzweg…"
```

우리가 붙인 게 아니라 **롯데ON 이 그렇게 부른다.** 셋으로 나눠 본다 —
A) 데이터 원본 문제 B) 그대로 보여주는 것이 맞는가 C) 별도 표시명 관리 가능한가.
🔴 **자르지 않았다.** 자르면 셀러가 판매자센터에서 보는 이름과 달라진다.

## 2. STEP 2 — Case A~E 분류

### Case A — 공통에 값 있는데 Commerce 가 못 쓴다 (버그/Resolver 누락)

**1건 — 업체상품번호 `epdNo`.**

```
SmartStore  sellerManagementCode  ← product.sku          자동
Coupang     externalVendorSku     ← variant.sku ?? sku   자동 (S-11 에서 단품폴백까지 넣음)
LotteON     epdNo                 ← form.codes.externalProductNo   🔴 셀러가 «직접 적는다»
```

🔴 코드의 주석이 스스로 이렇게 적어 놓고 있다 —
`build-payload.ts:118  /** 업체상품번호(epdNo) — 우리 쪽 식별자. jobKey/sku 등에서 만든다. */`
**만들지 않는다.** 화면이 묻는다. 두 채널이 자동으로 채우는 «우리 쪽 식별자» 를
롯데ON 에서만 셀러에게 적게 하고 있다.

🔴 그리고 내 첫 표가 이것을 틀렸다 — `eitmNo`(단품 SKU, 자동)와
`epdNo`(업체상품번호, 수동)를 **같은 것으로 묶어** 「화면만 비어 보인다」고 적었다.
두 개는 다른 필드다.

그 밖의 상품 공통값(상품명·가격·재고·옵션·이미지·상세·제조사·모델명)은
세 채널 모두 payload 까지 흐른다. 🔴 CEO 께서 보신 나머지 「비어 있음」은
공통값 누락이 아니라 **아래 B 가 405 로 막힌 것**이다.
