## 5. ⑤ `700005621LBL` — 유입 경로 확정 + 🟡 **안전 후보 하나**

### 5-A. 경로 (코드로 확정)
```
seller-facts.ts:208   brandModelCode = extractLabeledProductCode(description)
                                       ?? **extractCodeLikeSlugSegment(slug)**
product-facts.ts:759  첫 slug 조각 · 길이 6~20 · `[a-z0-9]+` · 글자와 숫자 **둘 다**
kids21 `/products/700005621lbl` → 첫 조각 12자 · 영숫자 혼합 ⟹ **통과 → 품번으로 승격**
```
🔴🔴 **그 함수 주석의 전제가 반증됐다** — 「판매처 재고번호가 여기 걸리지 않는지가
중요한데 실측한 두 형태 모두 안전하게 빠진다」고 적혀 있는데, **kids21 형태가 그 둘에 없었다.**

### 5-B. slug → 품번 승격 **전수 13건**
```
🟢 bobochoses.com / .co.jp  **10건** — 전부 **진짜 브랜드 품번**(`b226ac010` · `b126ai018` …)
🔴 kids21.com               **3건** — 전부 **샵 자체 SKU**
   `700005621LBL`(light blue) · `700002005GRN`(green) · `700002037MLT`(multi)
```

### 5-C. 🟡 안전한 식별 가능성 — **하나 있다**
```
관측  승격된 13건에서 **진짜 품번은 전부 «글자로 시작»** 하고
      **샵 SKU 는 전부 «숫자로 시작»** 한다 — 이 표본에서 **완전 분리**
후보  「첫 slug 조각이 숫자로 시작하면 브랜드 품번으로 쓰지 않는다」
🟢 이 표본에서 **잃는 것이 0** 이다 — PèPè 의 `01195-VERNICE-NERO` 는 첫 조각이
   `01195`(숫자만)라 **현재도 `/[a-z]/` 조건에서 이미 떨어진다**(승격 목록에 없다)
🔴 그러나 **N=13 · 브랜드 2곳** 이다. 숫자로 시작하는 진짜 브랜드 품번 체계가
   있는지는 **미측정** 이다. 그리고 그것은 **새 규칙** 이다.
🔴 **수정하지 않았다**(CPO 지시). 가능성만 적는다.
```

### 5-D. 🟢 그리고 지금은 **안전한 방향으로 틀린다**
```
잘못된 품번이 들어와도 `compareModelCode` 가 **conflict** 를 내고 결과는 **EXCLUDED** 다.
🟢 즉 False SAME 이 아니라 **과잉 차단** 쪽으로 틀린다(S2-4 가 그 1건이다).
🔴 고치면 recall 이 올라가지만, 그때는 **잘못된 품번이 SAME 에 기여** 할 수 있다.
```
