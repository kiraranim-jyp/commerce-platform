## 🔴🔴 이 WU 가 가른 것 — **「검색」이 아니라 「가격 해석」**

🔴 CPO(2026-10-22): 「국내와 해외의 차이는 **검색 시스템이 아니라 가격 해석** 이다」.
🔴🔴 **그런데 코드는 두 시장에 «같은 해석» 을 쓰고 있었다** — `priceGuideHeadline`
하나를 두 블록이 공유해서 **국내에도 「범위」가, 해외에도 「범위」가** 나왔다.

```
🇰🇷 국내  →  «시장 가격대»     `domesticPriceBand` + `domesticBandText`
             BAND   `KRW 89000 ─ 95000` + 라벨 **「국내 시장 가격대」**
             SINGLE `KRW 89000 · 가격대 확정 불가`   ← 🔴 **1개는 가격대가 아니다**
             NONE   통화가 섞이면 **가격대를 만들지 않는다**(환산 금지의 귀결)
🌎 해외  →  «최저 확인가»     `overseasLowestText`
             단일 통화 `최저 확인가 USD 58`          ← 🟢 **단정 가능**
             복수 통화 `최저 확인가 CAD 64 · GBP 37 · USD 58` + 「하나로 합치지 않습니다」
🟢 owner 는 **`marketPriceHeadline(g)` 하나** — 호출부(MarketBlock)는 분기하지 않는다
```

### 🔴🔴🔴 CPO 예시를 그대로 구현하지 «않은» 곳 둘 — 먼저 적는다

```
⒜ 🔴 **「최저 USD 58」을 단정하지 않았다**(통화가 섞일 때)
   CPO 예시는 **단일 통화 가정** 이다. 🔴 그런데 실측 S1 은 **CAD 64 · GBP 37 · USD 58**
   세 통화다 — 거기서 「GBP 37 이 최저」로 적으면 **거짓** 이다(비교에 환산이 필요하고
   환산은 `overseas-reference` 계약이 금지한다).
   🟢 그래서 **통화별 최저** 를 적고 **그 사실을 문장으로도** 말한다.
   🔴 변이 P2(통화 무시하고 숫자만 비교해 최저 하나 고르기)가 **4 FAIL** 로 잠겼다
⒝ 🔴 **「₩89,000」· 「약 9만원대」를 만들지 않았다**
   `₩` 기호 — 이 영역의 계약이 「통화 그대로 · **기호로 바꾸지도 않는다**」이고
   `wu-056r1` 이 해외 구역의 `₩` 0 을 글자로 잠그고 있다 ⟹ `KRW` 를 유지했다
   「약 9만원대」 — 금액을 만원 단위로 **버림** 해야 나오고, 가격대가 89,000~105,000
   이면 **거짓** 이 된다(새 반올림 규칙 = 새 정책) ⟹ **관측 숫자를 그대로** 적었다
   🟡 둘 다 **CPO 가 원하면 한 줄** 이다 — 다만 지금 바꾸면 계약 축을 건드린다
```
