## 4. 🔴🔴 반사실 — ΔSAME 과 ΔFalse SAME 을 **같이** 쟀다

CPO 요구를 그대로 구현했다: `추가 정보 → MI SAME 증가 → False SAME 변화`.

- **ORACLE** = 추출기가 **완벽했다면**. GT SAME 쪽만 채운다 → **Recall 상한**
- **ADVERSARIAL** = 추출기가 **틀렸다면**. GT DIFFERENT 에도 들어간다 → **FP 천장**

| 레버 | MI SAME | **ΔSAME** | **ΔFalse SAME**(천장) | 판정 |
|---|---|---|---|---|
| 지금 JSON-LD 에 있는 것 **전부** | 10 | **0** | 0 | 🔴 레버 없음 |
| **색상 — 완벽 추출** | 10 | **0** | 0 | 🔴🔴 **반증** |
| 후보 브랜드 — 완벽 추출 | 12 | **+2** | **0** | 🟢 안전 |
| 원상품 브랜드 공백 복구 | 11 | **+1** | **0** | 🟢 안전 |
| **브랜드 양쪽(원상품+후보)** | **13** | **+3** | **0** | 🟢 **유일한 안전 조합** |
| + 품번(sku→brandModelCode) | 15 | +5 | **+5** 🔴 | ❌ **탈락** |

### 읽는 법 셋 (🔴 넘겨 읽지 않는다)

1. 🔴🔴 **색상은 레버가 아니다.** 9건의 색상 결손을 **완벽하게** 메워도 SAME 이
   **하나도** 늘지 않는다. 다른 축이 **동시에** 모자라기 때문이다 — P0 는 **반증됐다.**
2. 🔴🔴 **품번은 수익과 위험이 1:1 이다.** +5 를 벌고 FP 천장도 **+5**. 「판매처 자신의
   SKU 를 브랜드 품번 칸에 넣는 것」이 정확히 ProductFacts 주석이 금지한 그 행위다
   → **CPO 기준(False SAME 0 유지)으로 구현 후보 탈락.**
3. 🟢 **브랜드만 ORACLE == ADVERSARIAL 이다**(둘 다 FP 0). 브랜드를 잘못 넣어도
   제목·품번 축이 막아서 거짓 양성이 생기지 않는다 — **구조적으로 안전한 축**이다.

### 뒤집힌 3건은 전부 **브랜드 공식몰**이다

```
S3 × 2  bobochoses.co.jp   (후보 브랜드 결손 복구)
S6 × 1  bobochoses.com     (**원상품** 브랜드 null 복구)
```

🔴 즉 브랜드 레버는 「아무 샵에서나」가 아니라 **공식몰 후보에서만** 걸렸다.

## 7. 🔴 구현하지 않았다 — 둘 다 «결정» 이 먼저다

안전 판정을 받은 브랜드 레버조차 **지금 구현할 수 없다**:

```
① 후보 브랜드 +2 → 🔴 JSON-LD 에 있는 브랜드(3건)로는 **ΔSAME 0** 이다.
     +2 는 «완벽 추출» 가정값이고, 그 추출 경로가 **지금 없다.**
② 원상품 브랜드 +1 → 🔴 복구 수단이 **도메인→브랜드 표** 다.
     그것은 Registry 성격이라 §12-0「Registry 확대 금지」와 정면으로 만난다
     (WU-009 ⒝ 와 **같은 자리**이고, 그때도 CTO 가 고르지 않았다).
```

🔴 그리고 **「브랜드 추출을 단순 보강」은 이미 반증돼 있다** — WU-009 실측:
`og:site_name` 을 브랜드로 쓰면 우리 원본 도메인 **25/26 이 멀티브랜드 리테일러**라
