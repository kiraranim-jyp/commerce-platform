## §7. ⑥ CPO 의사결정 요청 — 셋으로 분리

### ⒜ 기존 정책을 유지한 채 해결 가능한 문제

```
① 🟢 **2차 선택적 증거 확인 방식 자체** — 이번에 대상 9건에 HTTP 10 으로 **2건을 찾았다**.
   근거: 전수 381 중 2.4% 만 봐서 신규 상향 2건 · 오판 0.
   예상 SAME 증가: 🔴 **측정된 것은 2건** 이다(일반화 금지 · 표본 9).
   위험: 🟢 낮다 — 조사 절차이고 판정 로직을 건드리지 않는다.
   🔵 결정 요청: **이 2단계 절차를 조사 표준으로 채택할 것인가.**
② 🟢 **1차 분류기를 «선별기» 로만 쓰기** — 전수에서 상향 후보 2건을 오탐 0 으로 집었다.
   🔴 단 **확대 효과는 0** 이므로 「SAME 증가 수단」으로 쓰지 않는다.
```

### ⒝ 운영 추출기 개선이 필요한 문제

```
① 🔵 **원상품 품번 구조화 저장**(우선순위 1) — 원상품 79/122 가 `sku` 빈값이다.
   🟢 근거: 후보행 253/381 이 그 원상품 소속이고, 판정근거가 전건
      `품번증거=unavailable (해외 CODE ↔ 국내 없음)` 을 적는다.
   🔴 예상 SAME 증가: **미측정** 이다. 🔴🔴 그리고 WU-080 이 「원상품 공백을 메우면
      보류→충돌로 악화」를 측정한 선례가 있다 ⟹ 🔵 **채우는 «방법» 을 CPO 가 정해야 한다**
      (URL slug 복구값을 그 칸에 쓸 것인가 · 그러면 ②와 같은 질문이 된다).
② 🔵 **브랜드 추출 실패 복구**(coupleshot 모양) — 브랜드 필드 null + 상세설명에 브랜드.
   🟢 근거: 전수에서 `UNCONFIRMED 43` · 그중 품번 MATCH 인 것 1건.
   🔴 예상 효과: **1건** ⟹ 🔴 단독으로는 효율이 낮다.
③ 🔵 **인코딩 손상 페이지**(EUC-KR 오디코딩) — 제목 토큰이 생기지 않는다.
   🔴 전수 빈도 **미측정** 이다(이번 조사에서 1건 관측).
```

### ⒞ SAME 판정 «정책» 변경이 필요한 문제

```
① 🔵🔵 **복구된 품번의 자격**(우선순위 2) — 추출기가 URL 에서 복구한 품번이 **34행에서
   MATCH** 인데 판정근거는 `unavailable` 로 남아 **식별자 경로가 닫힌다**.
   🔵 결정 요청: 「URL slug 복구 품번을 식별자 증거로 인정할 것인가」.
   🔴🔴 **위험이 크다** — 식별자 경로는 `EXACT` 를 만들고 그것은 **가격 집계에 직접 들어간다**.
      그리고 품번 CONFLICT 40건이 **같은 복구 경로** 를 쓰므로 오탐 방향도 함께 열린다.
   🔴 CTO 는 이 변경의 오판 위험을 **측정하지 못했다**(human GT 39건은 다른 분모다).
② 🔵 **제목 겹침 0 의 처리** — 139/381 이고 「실제 다름」과 「언어 차이」를 **같은 말로** 만든다.
   🔴 그러나 브랜드·품번이 둘 다 일치하는 것은 **1건** 이다 ⟹ 효과 대비 위험이 크다.
   🔴 기존 8축 CLOSED 영역이라 CTO 가 열지 않았다.
③ 🔴 **상세설명의 운영 판정 연결** — 금지 유지. 이번 조사에서 그 모양은 **3건** 이고
   정밀도 재측정 분모가 여전히 없다.
```
