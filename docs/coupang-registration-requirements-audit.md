# 쿠팡 등록 필수값 전체 재조사 (Priority 2 사전 조사)

목적: "쿠팡 등록 API를 호출한 뒤에야 필수값 부족을 알게 되는 구조"를 없애기 위해,
현재 `buildCoupangPayload()`/`coupang.adapter.ts`/`missingSellerConfigFields()`가
실제로 무엇을 요구하는지, 그리고 아직 전혀 다루지 않는 필드가 무엇인지 전부 나열한다.

## ⚠ 가장 중요한 발견 — `overseasPurchased`가 사실과 반대로 고정돼 있었다

`packages/listing/src/coupang/build-payload.ts`에서 배송 정책을 정하는 바로 위
주석은 "해외 URL을 소싱해서 등록하는 CartPilot 특성상..."이라고 명시하는데,
바로 아래 `overseasPurchased` 필드는 `"NOT_OVERSEAS_PURCHASED"`로 하드코딩되어
있었다 — CartPilot이 등록하는 모든 상품은 정의상 해외 URL에서 소싱한 것이므로
이 값은 사실과 반대다. 쿠팡이 이 필드로 통관/판매 규제를 다르게 적용할 수 있어
실제 등록 성공률 또는 규정 준수에 영향을 줄 수 있는 항목이라 이번 조사에서 가장
먼저 고쳤다(`overseasPurchased: "OVERSEAS_PURCHASED"`로 수정).

`pccNeeded`(개인통관고유부호 필요 여부)는 함께 고치지 않았다 — 목록통관 한도/품목
분류(HS Code)에 따라 달라지는 값이라 CartPilot이 지금 갖고 있는 정보(가격만)만으론
정확히 판단할 수 없고, PCC 수집 흐름 자체가 없다. 실제 등록 시 쿠팡이 이 값을
어떻게 요구하는지 Wing 계정으로 직접 확인이 필요하다 — 다음 스프린트 후보로 남긴다.

## 분류: 자동 생성 가능 / AI 추천 가능 / 사용자 필수 입력

| 필드 | 분류 | 현재 상태 |
|---|---|---|
| 상품명 | 자동 생성 | ✅ 크롤러가 추출, 사용자가 수정 가능 |
| 브랜드 | 자동 생성 | ✅ 크롤러가 추출(JSON-LD/Shopify JSON 등), 사용자가 수정 가능 |
| 이미지 | 자동 생성 | ✅ 크롤러+이미지 파이프라인이 처리 |
| 설명 | 자동 생성 | ✅ 크롤러가 추출, 사용자가 수정 가능 |
| 옵션 | 자동 생성(원본에 있으면) | ⚠ 원본 사이트에 옵션이 없으면 구조적으로 못 채움 — WARNING으로만 처리 |
| 판매가 | 자동 생성(환율 추정) | ✅ `convertToKrw` — 사용자가 직접 입력해 확정할 수도 있음 |
| 카테고리 | AI 추천 | ✅ AI 추천 + 검색 UI 있음. **문제: 사용자가 실제로 확정 안 해도 등록 버튼이 눌린다** (아래 참고) |
| 상품 속성(attributes) | AI 추천 가능(미구현) | ❌ 항상 빈 배열 — 쿠팡 카테고리 메타정보 조회 API 미연동. 카테고리가 필수 속성을 요구하면 쿠팡이 API 단에서 거부함(현재는 이 실패가 COUPANG_API 단계에서만 드러남) |
| 고시정보(notices) | AI 추천 가능(미구현) | ❌ 항상 빈 배열 — attributes와 동일한 이유 |
| 키워드(SEO) | AI 추천 | ✅ `seoTitle`/`seoDescription`/`keywords` 필드는 있으나 쿠팡 payload에는 아직 안 씀(검색 태그는 옵션값 재사용) |
| 출고지 | 사용자 필수 입력 | ✅ 설정 페이지에서 1회 입력 |
| 반품지(코드/명/연락처/우편번호/주소) | 사용자 필수 입력 | ✅ 설정 페이지에서 1회 입력 |
| 택배사 | 사용자 필수 입력 | ✅ 설정 페이지에서 1회 입력 |
| Wing 계정 ID | 사용자 필수 입력 | ✅ 설정 페이지에서 1회 입력 |
| 쿠팡 API 인증(Access/Secret/Vendor ID) | 사용자 필수 입력 | ✅ 설정 페이지에서 1회 입력 |
| A/S 연락처 | 사용자 필수 입력 | ❌ 별도 필드 없음 — 현재 반품지 연락처(companyContactNumber)를 그대로 재사용하고 있어 실제로는 "A/S 연락처"라는 개념 자체가 UI/데이터에 없음 |
| 사업자 정보(사업자등록번호 등) | 사용자 필수 입력 | ❌ 전혀 없음 — 쿠팡 Wing 계정 자체에 이미 등록돼 있어 상품 등록 API가 요구하지 않는 값일 가능성이 높지만(계정 레벨 정보), 카테고리에 따라 원산지/제조사 신고가 필요한 경우가 있어 재확인 필요 |
| 성인상품 여부 | 사용자 필수 입력(카테고리별 상이) | ❌ `adultOnly: "EVERYONE"` 하드코딩 — 카테고리가 성인 인증이 필요한데 EVERYONE으로 보내면 쿠팡이 거부하거나, 반대로 실제 일반상품인데 성인상품으로 분류해야 하는 카테고리도 있음 |
| KC 인증 대상 여부 | 사용자 필수 입력(카테고리별 상이) | ❌ 전혀 모델링 안 됨 — 유아용품/전자제품 등 KC 인증이 필요한 카테고리는 인증번호를 attributes/certification 형태로 제출해야 하는 경우가 있음. `packages/marketplace`에 `certification` 필드가 CanonicalProduct에는 있지만(`DEFAULT` 값 고정) 쿠팡 payload에는 전혀 반영 안 됨 |
| 해외구매대행 여부 | 자동(고정값이어야 함) | 🔧 이번에 수정 — 위 "가장 중요한 발견" 참고 |
| 병행수입 여부 | 자동(고정값이어야 함) | `parallelImported: "NOT_PARALLEL_IMPORTED"` — CartPilot은 브랜드 공식 판매처가 아닌 해외 쇼핑몰에서 소싱하므로 대부분 맞는 값으로 보이나, 정품 병행수입 케이스도 있을 수 있어 100% 확신은 아님(현재 범위에서는 그대로 유지) |
| 개인통관고유부호 필요 여부(pccNeeded) | 카테고리/통관 방식별 상이 | ❌ 위 "가장 중요한 발견" 참고 — 다음 스프린트로 이월 |

## 이번 Sprint에서 실제로 고친 것

1. **`overseasPurchased` 하드코딩 값 수정**(사실과 반대였던 것) — `packages/listing/src/coupang/build-payload.ts`.
2. **카테고리 미확정 상태에서 LIVE 등록이 가능했던 구조적 버그 수정** — `categoryFieldRule`이 WARNING이라 `registrableScore`/`READY` 게이트를 통과해버렸다. LIVE 등록 직전에 카테고리 확정 여부를 별도로 강제 검사하도록 고쳤다(client 쪽에서 등록 버튼 자체를 막음 — server 쪽 CP001은 그대로 안전망으로 남겨둔다).
3. **통합 Pre-flight 체크리스트 UI** — 상품 validation(브랜드/이미지/가격/설명)과 판매자 설정(출고지/반품지/택배사/카테고리)을 하나의 ✓/✗ 목록으로 합쳐서, 등록 버튼을 누르기 전에 보여준다.

## 다음 스프린트로 이월하는 것 (이번엔 손대지 않음)

- **쿠팡 카테고리 메타정보 조회 API 연동** — attributes/notices를 실제로 채우려면
  카테고리별 필수 속성 스펙을 쿠팡 API로 조회해야 한다. 이게 없으면 특정 카테고리는
  이 문서의 Pre-flight 체크리스트를 전부 통과해도 API 단계(COUPANG_API/API005)에서
  실패할 수 있다 — 근본 해결은 아니고 사전 노출은 여전히 안 됨.
- **A/S 연락처를 반품지 연락처와 분리** — 지금은 개념이 하나로 뭉쳐 있다.
- **성인상품 여부/KC 인증 대상 여부** — 카테고리 확정 시점에 사용자에게 물어봐야
  하는 값들인데, 이것도 카테고리 메타정보 API 연동과 묶어서 처리하는 게 자연스럽다.
- **pccNeeded(개인통관고유부호)** — 실제 Wing 계정으로 값을 어떻게 요구하는지
  확인 후 결정.
