## 1. `0090` A/S 책임자 — 저장 구조 «설계»

### 1-1. 기존 의미 체계와 충돌하는가 → **충돌하지 않는다. 다만 이웃이 가깝다**

| 기존 값 | 의미(코드 주석 그대로) | `0090` 과의 관계 |
|---|---|---|
| `SellerSettings.manufacturer` | 「판매자 본인의 제조자(수입자). 🔴 브랜드가 아니다」 | 🟡 **가깝다** — 이미 «판매자 사업체 이름» 모양이다 |
| `SellerSettings.asContactNumber` | 「A/S 연락처」 | 🟢 **짝이다** — 같은 축의 나머지 반쪽 |
| `product.manufacturer` / `product.importer` | 상품의 제조자·수입자(고시 `0070`) | 🟢 다른 축 — 상품별로 다르다 |

🔴 `manufacturer` 가 가깝다는 것이 **「그것을 쓰자」는 뜻이 아니다.** 실제로 같은
문자열일 수는 있어도 «판매자의 제조자 자격» 과 «A/S 를 책임지는 업체» 는 다른
사실이고, 고시는 후자를 묻는다. CPO 가 이미 대체를 금지했다.
다만 **UX 상 셀러가 같은 값을 두 번 칠 가능성**은 설계에 적어 둔다.

### 1-2. 이 축은 롯데ON 만의 것이 아니다 → **COMMON 이 맞다**

```
네이버   afterServiceDirector (자유 텍스트) ← 지금 asContactNumber «전화번호» 가 들어간다
         afterServiceTelephoneNumber      ← companyContactNumber
쿠팡     afterServiceInformation · afterServiceContactNumber  ← 실측상 «비어 있음»
롯데ON   고시 0090 「A/S 책임자와 전화번호」 ← 업체명 + 전화번호 «둘 다»
```

세 채널 모두 A/S 축을 갖는다. 🔴 그리고 네이버는 「책임자」 칸에 **전화번호**가
들어가 있다 — 의미가 어긋나 있지만 **Production 검증된 경로라 이번에 건드리지 않는다**
(기록만 남긴다).

### 1-3. 설계 (구현하지 «않는다»)

```
저장 위치   COMMON SELLER SETTING   (asContactNumber 와 같은 자리)
타입        string | null
DB 컬럼     as_company_name         ← 기존 규약 그대로 snake_case
                                      (as_contact_number · quality_guarantee …)
camelCase   asCompanyName
UI 라벨     「A/S 책임 업체명」
UI 도움말   「고시는 업체명과 전화번호를 «모두» 요구합니다. 제조사명이나
             배송 프로필 이름이 아니라, A/S 를 실제로 책임지는 업체 이름입니다.」
연결점      build-context.ts:250  sellerAsCompanyName: null
                                → commonSellerSettings.asCompanyName
```

🔴 **연결점은 «한 줄» 이다.** 이미 `sellerAsCompanyName` 이라는 이름으로 배선이
뚫려 있고 `null` 이 박혀 있을 뿐이다 — 그 자리에 설정값을 넣으면 `0090` 이 풀린다.

🔴 다른 채널에 자동으로 흘려보내지 «않는다». 네이버·쿠팡 payload 는 이번에 바꾸지
않는다(각 채널의 A/S 의미가 같은지 확인된 바 없다).

## 3. `1830` 크기ㆍ체중의 한계 — 🟢 **공식 규칙을 «찾았다». 그리고 1830 에는 없다**

공식 PDF 원문을 한글까지 추출해(15쪽 · 한글 10,658자) 문서 «전체» 를 검색했다.

### 3-1. 롯데ON 은 「해당없음」을 **항목별로 «명시»** 한다

```
07·08·09·10  에너지소비효율등급  「…대상 상품이 아닐 경우 "해당없음"으로 입력해주세요.」
16 0400      허가·인증·신고번호   「신고 대상 의료기기가 아닌 경우 "해당없음"으로 기재해주세요.」
16 0380      정격전압, 소비전력    「전기용품이 아닌 경우 "해당없음"으로 기재해주세요.」
26 0880      쪽수                 「전자책의 경우 "해당없음"으로 기재해주세요.」
37·38 1400   인증·허가 사항        「해당 사항이 없을 경우 "해당 없음"으로 기재해주세요.」
39 1540      어린이보호포장 유무    「해당사항이 없을 경우 "해당 없음"으로 기재해주세요.」
20·21·22     수입 관련 문구        「수입품이 아닌 경우 "해당없음"을 기재해주세요.」
39 0580      제조연월·유통기한      「유통기한의 경우 해당 없는 제품은 «생략 가능»」 ← 생략도 명시한다
```

즉 **「해당없음」도 「생략」도 롯데ON 이 «쓸 자리에는 써 둔다».**

### 3-2. 그런데 품목 23 `1830` 에는 그 문구가 «없다» [확정 · 원문]

```
23 1830 7. 크기ㆍ체중의 한계
착용 또는 탑승용 어린이제품과 같이 크기ㆍ체중에 제한이 있는 품목의 경우
반드시 기재해주세요.
Y
```

필수 `Y`, 그리고 **「해당 없을 때」에 대한 언급이 전혀 없다.**

🔴 **그러므로 우리가 고를 수 없다.** 다른 항목에서 쓰이는 `"해당없음"` 을 여기 옮겨
적는 것은 **패턴을 근거로 한 추측**이고, 이 문서는 그 지시를 «쓸 자리에는 쓴다» 는
것이 방금 확인됐다. 안 쓴 것은 안 쓴 것이다.

→ **`UNKNOWN` 유지. 자동 문자열 생성 0건.** 문의 문장(정확해졌다):

> 품목코드 23 어린이제품의 항목코드 1830 「크기ㆍ체중의 한계」는 필수여부가 Y 인데
> 작성 가이드라인은 「제한이 있는 품목의 경우」라는 조건문입니다. 착용·탑승용이
> 아니어서 크기·체중 제한이 없는 상품(예: 일반 아동 상의)은 `pdArtlCnts` 에 무엇을
> 기재해야 합니까? 다른 항목들처럼 `"해당없음"` 으로 적으면 됩니까, 아니면
> `pdItmsArtlLst` 에서 해당 항목을 생략해야 합니까?

### 3-3. 🔴 덤 — `notice-schema.ts` 에 전사 «누락» 이 하나 있다

품목 23 `0070` 의 공식 가이드라인이 우리 스키마에 **빠져 있다.**

```
공식   23 0070 9. 제조자, 수입자
       「구성품 별 제조자가 다른 경우 각 구성품의 제조자, 수입자를 기재해주세요.
        병행수입의 경우 '병행수입'으로 기재해주세요.」
우리   { code: "0070", label: "제조자, 수입자", required: true }   ← guideline 없음
```

나머지 12항목의 가이드라인은 원문과 «정확히» 일치한다(대조 완료). 이 하나만 비었다.

🔴 **그리고 이 문구가 사업 판단과 얽힌다** — 「병행수입의 경우 '병행수입'으로
기재」인데, 같은 품목의 `0200`(KC)은 「어린이제품은 구매대행/병행수입을 선택할 수
없습니다」라고 적는다. **두 문장이 같은 품목 안에서 서로 당긴다.**
해석하지 않고 그대로 올린다 — §4 와 함께 공식 확인 대상이다.
