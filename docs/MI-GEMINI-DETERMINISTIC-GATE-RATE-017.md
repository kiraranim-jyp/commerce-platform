# MI-GEMINI-DETERMINISTIC-GATE-RATE-017 — 게이트 적중률 실측

> 🔴🔴 **Gemini API 호출 0.** 🔴 단 **「무료」가 아니다**(CPO 명시) — 국내 판매처에
> 실제 HTTP **111 요청**(상품당 4.27)을 보냈다. 「비용 0」이 아니라 **「Gemini 비용 0」** 이다.
> 🔴🔴 **결과는 게이트에 불리하다 — 적중률 3.8%.** 그대로 적는다.

---

## 1. 결과 (`sample 상품 N=26` · 아동 17 · 테니스 9)

```
전체 상품                     26
deterministic very_high        **1**
적중률                        **3.8%**
🟢 Gemini 호출 필요            **25 (96.2%)**
```

### 카테고리별

| | 상품 | very_high | 적중률 | 후보 0 인 상품 |
|---|---:|---:|---:|---:|
| 아동 | 17 | **1** | **5.9%** | 0 |
| 테니스 | 9 | **0** | **0.0%** | **9** |

### 🔴🔴 이유 — `matchLevel` 분포가 설명한다 (후보 단위 · 총 175)

```
low        **173**
medium       **1**
very_high    **1**
🔴 `high` 는 **0 건** 이다.
```

→ 🔴 **이 시스템에서 `very_high` 는 구조적으로 거의 나오지 않는다.**
🟢 헌장 §12 가 이미 적어 둔 사실과 정합한다 — 「matchLevel 이 전건 **low** 다 —
medium 도 없다. 「high 문턱에 걸렸다」가 아니라 **점수가 거의 0** 이다」.
🟢 이번 측정이 그것을 **N=26 · 후보 175** 로 확증했다.

## 2. 🔴🔴 그래서 결론 — **이 게이트만으로는 비용이 거의 안 줄어든다**

```
🔴 WU-016 의 deterministic 게이트는 **구조적으로 옳고 비용이 0** 이지만
   이 표본에서 **상품 1건** 만 걸러낸다. Gemini 는 여전히 **96.2%** 에서 호출된다.
🟢 그래도 **제거하지 않는다** — 공짜 보험이고, threshold 를 건드리지 않는
   유일한 정책 안전 술어다. 🔴 다만 **비용 레버로 과대평가하면 안 된다.**
```

### 🔴 「게이트를 낮추자」는 생각을 데이터가 먼저 막는다

```
`high` 로 낮춘다?  → 🔴 `high` 가 **0 건** 이다. 낮춰도 적중률이 그대로다.
`medium` 으로?     → 🔴 `medium` 도 **1 건** 이다. 2/26 = 7.7% 가 된다.
→ 🔴🔴 즉 **threshold 완화로 해결되지 않는다**(그리고 완화는 금지 사항이다).
   게이트가 안 걸리는 이유는 문턱이 아니라 **점수가 거의 0** 이기 때문이다.
```

## 3. 🟢 그래서 실제로 비용을 줄이는 레버는 **다른 둘** 이다

WU-016 이 넣은 장치 중 **효과가 다른 쪽에 있다**:

```
① deterministic 게이트(very_high)   🔴 적중률 **3.8%** — 효과 거의 없음(실측)
② 당일 가드(ALREADY_CHECKED_TODAY)  🟢 **수동 재확인 반복을 전부 흡수** 한다
   🔴 단 그 효과도 **미측정** 이다 — 셀러가 「가격 다시 확인」을 하루에 몇 번
      누르는지 모른다. 로그가 없다. 「0 회」로도 「많다」로도 적지 않는다.
③ Primary 불가 시 호출 0 (NO_PRIMARY_QUERY)  🔴 발생률 **미측정**
```

### 🔴 새로 보이는 레버 하나 — **그런데 정책 결정이다**

```
🔴 테니스 9/9 가 **후보 0** 이다. 그리고 그 원인은 이미 확정돼 있다 —
   TENNIS scope 샵이 **1곳(스카이스포츠)** 뿐이고 그 샵의 Sergio Tacchini
   교집합이 **0** 이다(선행 WU 실측 · 국내 취급처 부재).
🔴 그런데 현재 게이트는 「후보 0」을 **「Gemini 필요」로** 센다 →
   테니스 전건에서 Gemini 를 부르게 된다.
🟡 WU-011 실측: Gemini 를 불러도 테니스는 **국내 KRW 가격 증거 0** 이었다.
→ 🔴 그러므로 「scope 에 쓸 수 있는 샵이 사실상 없으면 Gemini 를 부르지 않는다」가
   비용 레버로 성립할 수 있다. 🔴🔴 **그러나 그것은 「그 카테고리에서 Discovery 를
   포기한다」는 제품 정책** 이고 CTO 가 결정할 수 없다 → CPO 판정 사안.
   🔴 구현하지 않았다.
```

## 5. 🔴 해석 한계 — 넘겨 읽지 않는다

```
🔴 적중률 3.8% 는 **이 표본(N=26)** 값이다 — 운영 전수(약 498 상품) 값이 아니다.
🔴 `very_high` 가 «옳은» 매칭인지 이 WU 는 보지 않았다 — **게이트 발화 여부만** 셌다.
🔴 후보 0 인 상품(9/26 = 34.6%)은 게이트가 발화하지 않아 「Gemini 필요」로 세어진다.
   그러나 그 상품은 Gemini 를 불러도 국내 후보가 없을 수 있다(테니스는 실측으로 그랬다).
🔴 테니스는 scope 샵이 1곳뿐이라 **구조적으로** 적중률이 0 이다 — 알고리즘 문제가 아니다.
🔴 당일 가드·NO_PRIMARY_QUERY 의 발생률은 **측정하지 않았다**(로그가 없다).
```

🔴 그래서 **「Gemini 호출을 X% 줄인다」로 적지 않는다.** 적을 수 있는 것은
「이 표본에서 게이트가 **1/26** 에서 발화했다」 하나다.
