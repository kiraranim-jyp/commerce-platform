## 3. 🔴 이번 실측이 «틀렸다고 밝힌» 것 셋

### ① P0-KC-03 의 전제 — 「실제 등록 11건이 전부 코드 기본값 경로」

**틀렸습니다.** 코드 기본값이 나간 것은 **5건(2026-08-03~04)뿐**이고,
**2026-08-04 이후 지금까지는 Settings 문구가 나가고 있습니다.**

```
소스 경로:  context.kcExemptionText || DEFAULT_KC_EXEMPTION_TEXT
내용이 코드 기본값과 «다른데» source 가 DEFAULT_VALUE 다
→ context.kcExemptionText 가 채워져 있다 = Settings 값이다
```
🔴 추측이 아니라 **출처 기록과 코드 경로가 함께 가리키는 결론**입니다.

그리고 「사람이 override 를 넣은 건 0건」도 틀렸습니다 — `USER_INPUT` 이 **3건**
있습니다(2026-08-02).

**🟢 다만 P0-KC-03 의 «게이트» 는 그대로 옳습니다.** Settings 값도
`source: "DEFAULT_VALUE"` 라서 확인 모달이 `autoFilled` 로 잡고 확인을 요구합니다.
**설명이 틀렸던 것이지 기능이 틀린 것이 아닙니다.**

### ② KC-COUPANG-02 §1 의 제 문장 — 「4dbd5eb 이전에는 "전체 상품 상세페이지 참조"」

**제가 틀렸습니다.** 사다리 끝이 `NOTICE_DEFAULT_CONTENT` 인 것은 맞지만,
**그 상수의 «값» 이 시간에 따라 바뀌었습니다.**

```
$ git log --until=2026-07-31 … | grep NOTICE_DEFAULT_CONTENT
const NOTICE_DEFAULT_CONTENT = "상세페이지 참조";        ← 그때
const NOTICE_DEFAULT_CONTENT = "전체 상품 상세페이지 참조";  ← 지금
```

🔴 **그래서 제 분류기의 `DETAIL_PAGE_REFERENCE` 칸이 0 으로 읽혔습니다.**
「그 경로가 쓰인 적 없다」가 아니라 **「지금 상수로 과거를 재서 못 알아봤다」** 입니다.

**교훈**: 현재 상수를 기준으로 과거 데이터를 분류하면 조용히 틀립니다.
이번에 살아난 것은 `OTHER` 일 때 내용 표본을 남겨 둔 덕분입니다 — 그게 없었으면
「옛 기본값은 쓰인 적 없다」는 **반대 결론**을 보고할 뻔했습니다.

### ③ 「아동의류 카테고리에 KC 칸이 없을지도 모른다」는 제 우려

**기우였습니다.** KC 고시 칸은 **35건 · 11개 이상 카테고리**에서 실제로 나갔습니다.

### 🔴 개인정보 — 실제로 막아야 했던 구멍이 있었습니다

`KNOWN_NOTICE_VALUES` 가 **`"소비자상담 관련 전화번호"` 와 `"A/S 책임자와 전화번호"`
칸을 `contactNumber` 로 채웁니다.** 「고시 content 를 전부 돌려준다」로 만들었으면
**전화번호가 응답에 실렸을 것입니다.**

그래서 값 대신 **분류**를 돌려주고, KC 칸이면서 분류로 설명되지 않을 때만 120자로
잘라 싣습니다. 연락처 칸은 이름에 「인증」이 붙어 걸리더라도 값을 싣지 않습니다.
**음성 대조**: 그 차단을 제거하자 전화번호 가드 2건이 정확히 FAIL 했습니다.

### 토큰

CPO 승인에 따라 **CTO 가 새 토큰을 발급해 Production 에 설정**했습니다
(`vercel env rm` → `add`, `Type: Sensitive`). 🔴 **값은 대화에 흐르지 않았습니다** —
제가 만든 값이라 받을 필요가 없었고, 저장소가 아니라 세션 스크래치패드에만
있습니다. 기존 토큰은 무효화됐고, 그 토큰을 쓰던 것은 CTO 프로브뿐입니다
(`coupang-product-get-raw` 도 같이 열렸습니다 — 세 번 막혔던 P1-2 가 풀립니다).
