# WU-120 — ②탈락 URL 의 MI counterfactual (측정 · 구현 0 · 가격 0)

> 🔴 CPO 2026-10-20: 「질문을 바꾼다 — 『상품 상세 URL 인가』가 아니라 **『MI 가 판단할
> 상품 근거를 얻을 수 있는가』**. ②탈락 URL 을 MI 까지 보내 **경우 A(AI 가 못 찾음) ↔
> 경우 B(우리가 버림)** 를 가른다. 효과가 없으면 **코드 수정하지 않는다.**」

## 1. 🔴 1차 CF 는 **질문에 답하지 못했다**(내가 같은 게이트를 두 번 쟀다)

```
②탈락 전수 — S1 **17**(🇰🇷 2 · 🌎 15) · S2 **13**(🇰🇷 3 · 🌎 10)
그 30건을 `factsFromProductUrl` 에 직접 넣었더니 **전건 `NOT_PRODUCT_URL`**
🔴🔴 그리고 **965ms 에 끝났다 = HTTP 0회** ⟹ 운영 owner 가 **모양 게이트에서 먼저 거부** 한다.
⟹ 🔴 「추출기를 우회했다」고 적었지만 실제로는 **같은 판별을 다시 통과시키려 한 것** 이다.
🟢 그래서 **국내 5건을 raw fetch 로 직접 받아** 다시 쟀다(그것이 CPO 가 물은 것이다).
```

## 2. 🟢🟢 국내 5건 직접 확인 — **A 와 B 가 갈렸다**

| URL | HTTP | `@type:Product` | 품번 등장 | 상품링크 패턴 | 분류 |
|---|---|---:|---:|---:|---|
| `luksusbaby.kr/collections/bobo-choses` ×2 | 200 | **0** | 0 | 0 | 🔴 **C**(상품 특정 불가) |

```
🔴🔴 **경우 B 가 실재한다** — 보몽드 **홈페이지 안에 품번 B226AC009 가 6번** 나오고
   상품 상세 링크 패턴이 **498개** 다. 즉 **그 페이지는 그 상품의 상세 링크를 갖고 있다.**
🟢 나머지 4건은 **진짜 상품 특정 불가**(`Product` 구조화 데이터 0 · 품번 0 · 링크 0)
   ⟹ 그 차단은 **올바르다**(C 는 계속 제외).
```

## 3. 🔴🔴 그런데 **증분은 0 이다** — 성공 기준을 충족하지 못한다

```
보몽드의 그 상세 URL(`goods_view.php?goodsNo=1000014021`)은 **이미 후보 풀에 있었다**
(WU-112 GT 에서 CEO 가 **SAME** 으로 판정한 그 후보다).
⟹ 🔴 홈페이지를 분해(1-hop)해도 **이 표본에서 새로 얻는 국내 후보는 0** 이다.
🔴 CPO 성공 기준은 「국내 SAME/SIMILAR 후보가 **실제로 증가**」이고 ⟹ **충족 실패.**
🔴 그래서 **코드를 한 줄도 바꾸지 않았다**(CPO §7·§8 그대로).
```

## 4. 🟡 그래도 **메커니즘은 기록한다**(다음 WU 의 재료 · CTO 가 구현하지 않았다)

```
「목록/홈 페이지 → 그 안의 상품 상세 링크 1-hop 추출 → 그 링크만 후보로」
🟢 가능하다 — 보몽드 홈에서 품번이 보이고 링크 패턴이 498개다
🔴 그러나 **새 생산자** 다 — 추가 HTTP(페이지당 1회 이상) · 링크 선별 규칙 · 그리고
   「목록을 후보로 쓰지 않는다」는 기존 판단(WU-052/073 HOLD)과 **직접 만난다**
🔴 효과가 이 표본에서 **0** 이므로 **CPO 승인 없이 열지 않는다**
```
