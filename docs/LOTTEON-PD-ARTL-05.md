**판정:** 2022년 11월에 만들어져 **2023-01-01 시행 개정을 반영한** 표이고,
**롯데ON 이 오늘도 API 87 문서에서 이 파일을 가리키고 있습니다.**
→ **롯데ON 기준으로는 현행**입니다.

🔴 다만 「공정위 고시가 그 뒤로 바뀌지 않았다」는 **제가 확정하지 못했습니다.**
「없다」가 아니라 「확인 못 함」입니다. 그리고 우리가 맞춰야 하는 계약은
공정위 고시가 아니라 **롯데ON API** 라는 점은 분리해 둡니다.

CPO 지시대로 **364행을 코드에 넣지 않았습니다.**

## STEP 3 — 🔴 우리 데이터와 대조 (핵심)

### 3-A. 먼저, 조사 보고 하나를 정정합니다

제가 돌린 조사가 「A/S·품질보증은 우리 시스템에 **입력 경로 자체가 없다**」고
보고했습니다. **틀렸습니다.** `lotteon_seller_settings` 만 보고 내린 결론이었습니다.

실제로는 **공통 `seller_settings`(migration 059)에 있습니다** —

```sql
manufacturer              text,  -- 판매자 본인의 제조자(수입자)
as_contact_number         text,  -- A/S 연락처
quality_guarantee         text,  -- 품질보증기준
kc_exemption_text         text,  -- KC/인증 기본 문구
default_country_of_origin text,  -- 원산지 기본값
```

그리고 **쿠팡은 이미 이 값들을 쓰고 있습니다**(`build-payload.ts:1131` —
「상품마다 다른 게 아니라 판매자 본인이 어차피 반복 입력할 상수」).

🔴 **즉 0080·0090 은 「데이터가 없는」 문제가 아니라 「롯데ON 만 연결이 안 된」
문제입니다.** 이것이 우리가 계속 말해 온 그 구조 그대로입니다 —
**Common 에 있고, 한 커머스만 안 쓰고 있다.**

### 3-B. 13항목 분류표

| 코드 | 항목 | 우리 쪽 출처 | 분류 |
|---|---|---|---|
| `0020` | 색상 | `color` — 실측 `Lavender` | 🟢 **AUTO** |
| `0410` | 재질 | `material` — 실측 `17% Recycled Cotton` | 🟢 **AUTO** |
| `0060` | 제조국 | `countryOfOrigin` — 실측 `Spain` | 🟢 **AUTO** |
| `0780` | 크기, 중량 | `optionGroups`(치수) + `weight`. **섬유는 치수 대체 가능** | 🟢 **AUTO** |
| `0800` | 취급방법·안전표시 | `careInstructions` | 🟡 **AUTO(부분)** — 「안전표시」가 별도인지 확인 필요 |
| `0080` | 품질보증기준 | `seller_settings.quality_guarantee` **있음** | 🟢 **AUTO(배선만)** |
| `0070` | 제조자, 수입자 | `manufacturer` + `importer` + `seller_settings.manufacturer` | 🟢 **AUTO/USER_CONFIRMATION** |
| `0090` | A/S 책임자와 전화번호 | `as_contact_number` **있음**. 🔴 그러나 **「책임자(업체명)」 칸이 없다** | 🟡 **부분 — 항목 추가 필요** |
| `0200` | KC 인증정보 | `childCertification` · `certificationType` | 🟡 **USER_CONFIRMATION**(번호는 만들 수 없다) |
| `0210` | 품명 및 모델명 | `itemName`/`modelName` **필드는 있으나 값이 없다**(N-3.44) | 🔴 **MISSING** |
| `0790` | 사용연령 | `recommendedAge` 필드 있음. 옵션 `4-5 Years` 와 **연결 코드 없음** | 🔴 **UNKNOWN** |
| `0220` | 동일모델의 출시년월 | **필드 자체가 없다** | 🔴 **MISSING(구조)** |
| `1830` | 크기ㆍ체중의 한계 | **필드 자체가 없다**. 조건부 항목 | 🟡 **NOT_APPLICABLE 후보 — 확인 필요** |

**요약: 7개는 배선만 하면 되고, 2개는 셀러 확인, 4개가 실제 난제입니다.**

### 3-C. 남은 넷을 정확히

**`0210` 품명 및 모델명** — 필드는 있고 값이 없습니다. 화면도 그렇게 말합니다
(「상품정보에 아직 없습니다」). 🔴 **`B226AC043` 같은 상품코드를 모델명으로
간주하지 않습니다** — CPO 지시 그대로이고, 원래 N-3.44 의 결론입니다.
필요한 것은 resolver 가 아니라 **source semantics 확인**입니다.

**`0790` 사용연령** — 옵션에 `2-3 Years`…`12-13 Years` 가 **실제로 있습니다**
(`optionGroups.values`). 그러나 그것은 **사이즈 축**이고, 고시의 「사용연령
또는 권장사용연령」과 같은 의미인지는 **확인되지 않았습니다.** 아동복에서
「6-7 Years 사이즈」는 체격 표기이지 연령 제한이 아닐 수 있습니다.
🔴 **자동 변환하지 않았습니다.**

**`0220` 동일모델의 출시년월** — 우리 어디에도 없습니다. 원본 사이트가 주는
값도 아닙니다. 🔴 **시즌 코드(`SS26` 등)를 출시년월로 바꾸지 않았습니다** —
`SS26` 은 시즌이지 출시년월이 아닙니다.

**`1830` 크기·체중의 한계** — 가이드라인이 「착용 또는 탑승용 어린이제품과 같이
크기·체중에 제한이 있는 품목의 경우」라고 조건을 답니다. 반바지에 해당하는지,
그리고 **해당하지 않을 때 무엇을 넣어야 하는지**(공란? 「해당없음」?)가
확인되지 않았습니다. 🔴 임의로 「해당없음」을 넣지 않았습니다.

## 결론 — BLOCKER 가 어디로 옮겨갔는가

```
이전:  고시 «항목코드» 를 모른다            → 전면 차단
지금:  코드는 안다. 값이 문제다.
        7개  배선만 하면 됨 (Common 에 이미 있음)
        2개  셀러 확인 (KC 번호 · A/S 책임자명)
        4개  🔴 실제 난제 (0210 · 0790 · 0220 · 1830)
```

그리고 그 4개 중 **셋은 「값을 만들면 안 되는」 것**이고(0210·0790·0220),
하나는 **「무엇을 넣어야 하는지 규칙을 모르는」 것**입니다(1830).
앞의 셋은 우리가 풀 문제이고, 뒤의 하나는 **문의로 풀립니다.**

### CPO 판단 요청

1. **0080·0090 배선** — Common 에 이미 있는 값을 롯데ON 이 못 쓰고 있는 상태입니다.
   이건 「새 기능」이 아니라 **누락된 연결**입니다. 별도 승인 없이 다음 구현
   스프린트에 넣어도 될지 정해 주십시오.
2. **A/S 「책임자(업체명)」 칸 추가** — 고시가 「업체명과 전화번호 모두」를
   요구하는데 우리에겐 번호만 있습니다. `seller_settings` 에 칸 하나가 필요합니다
   (= DB migration → **STOP 조건**이므로 먼저 올립니다).
3. **`0790` 의미 확인** — 「사이즈 축 `6-7 Years`」와 「고시 사용연령」이 같은
   개념인지. 문의 대상으로 넣을지, 아니면 셀러 확인 항목으로 둘지.
