> CPO 지시(2026-09-28): 화면보다 먼저 `payload → validator → Readiness` 를 끝까지 민다.
> 추측값 생성 ❌ · migration ❌ · 실제 API 호출은 CTO 권한 밖.

---

## 0. 결론 — 🔴 **등록을 막는 것은 고시가 아니라 «둘» 이다**

```
===== 아직 READY 가 아닌 항목 =====
  oplcCd        원산지코드      MISSING
  sftyAthnLst   안전인증(KC)    BLOCKED
```

그리고 그 둘을 채우면 —

```
===== 원산지·KC 를 채운 뒤 남은 항목 =====
  (없음)
```

**셀러가 화면에서 두 가지만 하면 등록 버튼까지 갑니다.**
① 원산지 고르기(롯데ON 이 준 239건 목록) ② KC 안전인증 입력.

## 1. 🔴 제 지난 보고를 정정합니다

지난 보고에서 「검증기는 13개 전부를 요구하므로 아직 Readiness 가 막습니다」라고
썼습니다. **틀렸습니다.** 검증기 조건은 이것입니다 —

```ts
// validate-payload.ts:188
if (channel.noticeArticles.length > 0 && channel.noticeArticles.every((a) => a.pdArtlCd && a.pdArtlCnts.trim()))
  ready("pdItmsArtlLst", "고시 항목");
```

**「1개 이상 · 실린 것은 전부 값이 참」** 이지 13개가 아닙니다.
소스를 다시 읽지 않고 기억으로 말했습니다.

## 2. API 87 직전 payload — 실측 출력

`register/route.ts` 와 «같은 순서»(`buildLotteOnContext → validate → buildPayload`)로
돌려서 뽑았습니다. 외부 호출은 하지 않았습니다.

```
===== API 87 직전 · pdItmsInfo =====
pdItmsCd = 23
  0780  2-3 Years, 4-5 Years, 6-7 Years, 8-9 Years, 10-11 Years, 12-13 Years
  0020  Lavender
  0410  17% Recycled Cotton
  0070  Bobo Choses
  0060  Spain
  0080  소비자분쟁해결기준에 따름
```

실린 6항목은 **전부 코드와 값을 갖습니다.** 빈 자리를 만들지 않았습니다
(`"pdArtlCnts":""` 가 없다는 것을 검사로 고정했습니다).

> 🔴 이 fixture 의 상품은 `careInstructions` 가 비어 있어 `0800` 이 빠졌습니다.
> 값이 있는 상품에서는 7항목입니다.

## 3. 6개 미충족 항목 — CPO 요청 4분류

| 코드 | 항목 | 분류 | 근거 |
|---|---|---|---|
| `0210` | 품명 및 모델명 | **상품 데이터 부재** | `itemName`/`modelName` 필드는 있고 값이 없다. 원본에서 신뢰성 있게 뽑을 방법이 없다는 것이 N-3.44 의 결론이다 |
| `0790` | 사용연령 | **상품 데이터 부재** | `recommendedAge` 필드는 있고 값이 없다. 옵션의 `6-7 Years` 는 사이즈 축이라 옮기지 않았다 |
| `0200` | KC 인증정보 | **판매자 확인 필요** | 실제 인증서의 번호다. 만들 수 없다 |
| `0090` | A/S 책임자와 전화번호 | **Common 설정 부재** | 연락처는 있고 **업체명 칸이 없다**. 고시는 둘 다 요구한다 |
| `0220` | 동일모델의 출시년월 | **현재 생성 불가(구조)** | 담을 자리 자체가 없다. 시즌 코드는 출시년월이 아니다 |
| `1830` | 크기ㆍ체중의 한계 | **현재 생성 불가(규칙)** | 자리도 없고, 해당 없을 때 무엇을 넣는지도 모른다 |

**이 6개 중 어느 것도 지금 등록을 막지 않습니다.** 검증기가 요구하는 것은
「1개 이상」이기 때문입니다.

---

## 4. 🔴 그러나 — 검증기 통과 ≠ API 87 통과

여기가 이 문서에서 가장 중요한 경고입니다.

| | 요구 |
|---|---|
| 공식 품목표 | 품목 23 의 **13항목 전부 필수(Y)** |
| 우리 검증기 | **1개 이상** |
| API 87 이 실제로 확인해 준 것 | **비어 있으면 거절**(`9999 상품품목항목코드 필수값이 누락`) |
| API 87 이 **확인되지 않은** 것 | 13개 미만이면 거절하는가 |

즉 **6개로 보냈을 때 롯데ON 이 받아 줄지는 아무도 모릅니다.**
그리고 그것이 CPO 께서 정하신 새 방식이 노리는 지점입니다 — **보내 보면 답이 옵니다.**

두 결과 모두 유용합니다.

- 받아 주면 → 등록이 뚫리고, 나머지 7항목은 품질 문제로 내려갑니다.
- 거절하면 → **어떤 항목을 요구하는지 오류 메시지가 알려 줍니다.** 우리가 추측할
  필요가 없어집니다(지금 `0220`·`1830` 에서 막혀 있는 그 추측입니다).

## 5. 🔴 그리고 정책 충돌 하나가 실측으로 드러났습니다

「원산지·KC 를 채우면 통과」를 확인한 시나리오에서 제가 쓴 값은 이것입니다 —

```
sftyAthnTypCd = CHL_CFM   [어린이제품] 안전확인
impPrxCd      = PUR_PRX   구매대행
```

둘 다 우리 코드에 실재하는 코드입니다(지어내지 않았습니다). 그런데 **공식
품목표의 품목 23 `0200` 가이드라인**은 이렇게 말합니다 —

> 「어린이제품 및 방송통신기자재는 개정 전안법 특례대상이 아니므로
>  **구매대행/병행수입을 선택할 수 없습니다.**」

**우리 검증기는 이 조합을 통과시킵니다.** 즉 등록을 시도하면 롯데ON 이
거절하거나, 받아 준 뒤 심사에서 반려할 수 있습니다.

🔴 이것은 제가 판단할 사안이 아닙니다(1:1 문의 A-1~A-6 에 들어 있습니다).
다만 **「첫 실제 오류」가 여기서 날 가능성이 높다**는 것은 미리 말씀드립니다.

  그리고 금지된 추정을 하지 않는지.

🔴 **fixture 결함을 한 번 겪었습니다.** 처음에 이미지와 옵션을 비워 두고 돌렸더니
`itmImgLst`·`itmLst` 가 BLOCK 으로 섞여 나와 「진짜 막는 것」이 흐려졌습니다.
실제 상품에 맞춰 이미지 1건·옵션 6건을 넣고 다시 쟀습니다.
