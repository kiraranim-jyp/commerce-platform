## 2. 기존 Commerce 영향 — «추가» 라면 0

| 채널 | 지금 무엇을 쓰는가 | 새 필드를 추가하면 |
|---|---|---|
| SmartStore | `originAreaCode` — Naver 자체 코드(`02>…` 계층, ISO 아님) + `origin-match.ts` | 영향 0 |
| Coupang | 고시 매칭으로 `countryOfOrigin` 텍스트 사용(3단 폴백) | 영향 0 |
| LotteON | `oplcCd` — 🔴 **ISO alpha-2** | 여기만 새 필드를 읽는다 |

🔴 **오해 하나를 미리 정리한다.** 쿠팡에 `COUNTRY_SYNONYMS` 가 있지만
`["제조국","원산지","country"]` — **어느 «고시 필드» 가 원산지인가**를 찾는
이름들이다. 국가명→코드 사전이 «아니다». CPO 께서 금지하신 것과 다른 물건이다.

## 3. 🔴 그런데 여기서 막힌다 — **누가 `ES` 를 채우는가**

CPO 금지사항을 그대로 적용하면 채울 길이 남지 않는다.

```
❌ "스페인" → ES 하드코딩
❌ "스페인(에스파냐)" 괄호 제거
❌ 임의 번역 / 동의어 사전
❌ Commerce별 국가명 매칭 로직
```

현재 Common 이 가진 것은 **크롤러가 긁은 자유 텍스트 하나**(「스페인」)뿐이다.
**어떤 규칙도 쓰지 않고 텍스트에서 코드를 얻는 방법은 없다.**

### 남는 길은 둘뿐이다

```
A-1  🔴 셀러가 Common 상품정보에서 «국가를 고른다»
     화면이 표준 국가 목록을 보여주고, 고른 결과로 ISO 코드를 저장한다.
     크롤러가 긁은 「스페인」은 «힌트» 가 되고 «키» 가 아니게 된다.

       원산지   [ 스페인  ▾ ]        ← 표준 목록에서 고른다
       저장     countryOfOriginCode = "ES"
                countryOfOrigin     = "스페인"   (표시명 · 기존 호환)

     ✅ 기존 원칙과 일치 — 「동일성은 셀러가 선언한다」
     ✅ 20~30개 Commerce 재사용 (대부분 ISO)
     ✅ 규칙을 «만들지 않는다» — 셀러가 정한다
     🔴 그러나 셀러가 상품마다 한 번 «더» 고른다 — 우리가 줄이려는 그 일이다
     🔴 그리고 표준 국가 목록은 «우리가» 들고 있어야 한다(ISO 3166 공개 표준)

A-2  🔴 크롤러가 ISO 코드를 «직접» 확보한다
     원본 페이지/JSON-LD 에 국가코드가 있으면 그대로 쓴다.
     shopify-market-probe · source-currency-policy 가 이미 국가/통화를 다룬다.
     ✅ 셀러 부담 0
     🔴 «원본에 원산지 국가코드가 있는지» 확인한 적이 없다 → 조사 필요
     🔴 그리고 「사이트 국가」와 「상품 원산지」는 다른 축이다(브랜드 국가 =
        원산지 가정은 `origin-match.ts` 주석이 이미 금지하고 있다)
```

## 4. 🔴 CPO 결정 요청 — 하나

`A` 를 승인하셨는데 **「누가 ES 를 채우는가」가 비어 있다.** 제가 정하면
금지사항(규칙 만들기)을 어기거나, 셀러 부담을 늘리는 결정을 제가 하게 된다.

```
A-1   Common 상품정보에 «국가 선택» 을 둔다 (셀러가 한 번 고른다)
      🔴 표준 국가 목록(ISO 3166)을 우리가 보유하는 것은 «허용» 하십니까?
         — 공개 표준이지만 「사전을 만들지 않는다」와 경계가 닿습니다.

A-2   크롤러가 ISO 코드를 확보할 수 있는지 «먼저 조사» 한다
      확보되면 자동, 안 되면 A-1 로 내려온다

A-1 + A-2   크롤러가 얻으면 자동, 못 얻으면 셀러가 고른다 (🔴 제 권고)
            ─ 기존 ProvenanceField 축과 그대로 맞는다:
              ORIGINAL(크롤러) / USER_EDITED(셀러) / REQUIRED(아직 없음)
```

## 5. 그리고 🔴 「자동 매핑 불가 시 fallback」 을 확정해야 한다

CPO 지시: *「자동 매핑 불가능하면 기존 선택 방식으로 안전하게 fallback」*

```
ISO 코드 있음   →  oplcCd = 그 코드 (239건 목록에 있는지 확인 후)
ISO 코드 없음   →  기존 방식: 셀러가 롯데ON 239건에서 고른다
목록에 없음     →  🟡 ETC 「상품상세 참조」가 채널 어휘에 있다
                   🔴 그것을 «우리가» 고를지 셀러가 고를지는 결정 사항
```

## ③ 관련 — 확인해 둔 것 하나

`importProxyCode` 를 «선택 구조» 로 바꾸되 한국어 라벨을 만들지 않으려면
화면에 무엇을 세울지가 문제다.

```
지금        자유 입력 + note 에 「PUR_PRX / PRL_IMP / NONE」
선택 구조   세 값을 고르게 한다 — 그런데 «무엇으로» 보여주는가
            코드 그대로 보여주면 「셀러에게 코드를 보여주지 않는다」와 부딪힌다
            한국어를 붙이면 「의미를 임의로 만들지 않는다」와 부딪힌다
```

🔴 **두 원칙이 여기서 충돌한다.** 제 권고는 **89 공통코드에 이 그룹이 있는지
먼저 확인**하는 것이다 — 있으면 채널이 준 `cdNm` 을 그대로 쓰면 둘 다 지킨다.
그룹 이름 후보(`IMP_PRX_CD` 류)는 추정이므로, 🔴 **화이트리스트에 이름을 추가하는
것부터 CPO 승인이 필요하다**(그 라우트는 「실제 응답을 확인한 뒤 이름을 적어
추가한다」가 규약이다).
