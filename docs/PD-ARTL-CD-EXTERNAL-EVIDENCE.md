## 1. A — 판매자센터: 🔴 CTO 가 할 수 없다

판매자센터 상품등록 화면을 직접 보려면 **로그인 자격증명**이 필요하다.
자격증명 입력은 제가 해서는 안 되는 행위이고, Production 자격증명은 Vercel
sensitive 라 읽을 수도 없다. 브라우저 확장도 이 세션에서 연결돼 있지 않았다.

→ **A 는 수행 불가.** 대신 B(금지됨)를 빼고 C(공개 자료)를 전수로 훑었다.

## 2. C — 공개 자료 전수 조사

### 2-1. 🟢 롯데ON API 센터 공식 문서 — **열린다**

`api.lotteon.com/apiService` 는 SPA 라 정적 fetch 로는 「Loading…」만 나온다.
렌더링을 거쳐 읽었다. 자격증명은 개입하지 않았다(공개 문서).

**API 87 「상품등록」**

| 필드 | 필수 | 형 | 설명 |
|---|---|---|---|
| `pdItmsInfo` | **O** | object | 상품품목고시정보 |
| `pdItmsCd` | **O** | string | 상품품목코드 (공통코드 `PD_ITMS_CD` 참조) |
| `pdItmsArtlLst` | **O** | array | 상품품목항목목록 |
| `pdArtlCd` | **O** | string(20) | 상품항목코드 |
| `pdArtlCnts` | **O** | string(4000) | 상품항목내용 |

공식 예시(그대로):

```json
"pdItmsInfo": {
  "pdItmsCd": "06",
  "pdItmsArtlLst": [
    { "pdArtlCd": "0020", "pdArtlCnts": "색상입력값" },
    { "pdArtlCd": "0060", "pdArtlCnts": "제조국입력" }
  ]
}
```

🟢 **이것이 이번 조사의 가장 큰 수확이다.** 우리 검증기가 등록을 막는 것이
«우리가 엄격해서» 가 아니라 **롯데ON 이 필수로 정해 둔 것**임이 외부 문서로
확인됐다. LIVE 거절(`9999 상품품목항목코드 필수값이 누락`)과 문서가 일치한다.

### 2-3. 🔴 제3자 연동 솔루션 자료 — 전부 해당 없음

윈셀링 · 넥스트엔진 · QX 연동 가이드 모두 **API 키 발급 / IP 등록 / 주문 동기화 /

## 3. 🔴 측정 품질을 정직하게 적는다

이 조사의 문서 판독은 **렌더링 프록시를 거친 요약**이다. 제가 DOM 을 직접
확인한 것이 아니다. 그리고 실제로 **두 판독이 서로 어긋난 지점이 하나 있다** —

```
87 상품등록      pdItmsArtlLst  필수 O
90 승인 상품 수정 pdItmsArtlLst  필수 표시 없음
```

등록과 수정이 실제로 다를 수도 있고(그럴듯하다), 판독이 틀렸을 수도 있다.
**저는 이 둘을 구분할 수단이 없다.** 편한 쪽을 골라 적지 않고 그대로 남긴다.

🔴 다만 **87 이 필수라는 판독은 독립 증거와 일치한다** — 우리 3차 LIVE 등록이
바로 그 필드 누락으로 거절됐다. 그래서 87 쪽 판독은 신뢰도가 높다.

## 4. 🔴 떠오른 가설 — 그리고 «쓰지 않는» 이유

상품정보제공고시는 **공정거래위원회가 정한 법정 고시**다. 품목별 항목명
(의류라면 소재·색상·치수·제조자·수입자·제조국·취급주의·품질보증·A/S…)은
법으로 고정돼 있다. 공식 예시의 `0020=색상`, `0060=제조국` 은 그 **법정 항목
순서에 번호를 매긴 것처럼 보인다**.

🔴 **그래서 어떻다는 것이 아니다.** 「~처럼 보인다」는 근거가 아니다.

- 순서가 품목마다 같다는 보장이 없다.
- `0020` 과 `0060` 사이에 우리가 모르는 항목이 몇 개인지 알 수 없다.
- 틀리면 **오등록**이다 — 소재 칸에 색상이 들어간 상품이 고객에게 나간다.

기록만 하고 **구현하지 않는다.** CPO 금지 조항과 정면으로 맞는다.
