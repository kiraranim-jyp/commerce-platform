# DISCOVERY E2E-02 — 따져 **실제 화면** 확인 절차

> 🔴🔴🔴 **이 문서는 CEO 가 읽는 절차서다.** CTO 가 Production 화면을 볼 수 없으므로
> 이 확인은 **CEO 만** 닫을 수 있다(아래 §0). 🔴 판정 기준(§4)은 **확인 항목(§3)과 분리** 돼 있다 —
> CEO 는 §3 만 보고 답하면 되고, GO/HOLD/NO-GO 판정은 §4 로 **CPO 가** 한다.

---

## 0. 🔴🔴 먼저 — **CTO 는 이 확인을 대신할 수 없다**

작업지시 §3 은 「CTO 는 로그인 후 실제 Production 따져 화면에서 … 확인한다」인데
**그것은 가능하지 않다.** 이 저장소에 이미 기록된 구조적 제약이다:

```
/pipeline · /today  →  **HTTP 307**(로그인 리다이렉트) · 실측 2026-10-28
/                   →  200
🔴 CTO 는 브라우저 세션/자격증명을 갖지 않는다(메모 `production-payload-is-unreachable`).
🔴 그래서 지금까지 모든 WU 가 「실제 따져 화면은 CEO 확인 1회로만 닫힌다」로 적어 왔다.
```

🟢 **CTO 가 대신 한 것** — 화면 «앞» 까지를 코드와 계약으로 확인했다(§5).
🔴 **CTO 가 못 한 것** — 픽셀. 그래서 아래 절차를 CEO 에게 넘긴다.

---

## 1. 🔴🔴🔴 가장 중요한 한 줄 — **「새 상품 분석」으로 들어가야 한다**

```
🟢 맞는 경로   /pipeline → **새 상품 분석** → 원상품 URL 붙여넣기 → 자동 진행
🔴 틀린 경로   기존 상품을 «열기»(목록/이어서 작업/새로고침)
```

**왜 그런가** — 자동 1회차 조사는 **스냅샷이 처음 만들어질 때만** 돈다
(`pipeline/page.tsx` 의 `isFirstInsert` 블록). 그리고 동일상품 후보는 **저장되지 않는
일시(transient) 값** 이라 `GET` 으로 다시 열면 **따라오지 않는다**(설계된 동작 · WU-049/059).

🔴 그러므로 **기존 상품을 열어서 후보가 없는 것은 「실패」가 아니다.** 그 경우 §4 의
판정표를 적용하지 않는다 — **다시 「새 상품 분석」으로** 들어가면 된다.
🔴 그리고 **F5(새로고침)도 같은 이유로 후보를 지운다.** 확인 중에는 새로고침하지 않는다.

## 2. 입력값 (복사해서 쓰면 된다)

```
화면     https://ttaejyo.vercel.app/pipeline   → 「새 상품 분석」
원상품   https://www.junioredition.com/en-kr/collections/bobo-choses/products/hug-hairy-monster-t-shirt-by-bobo-choses
상품     Bobo Choses · B226AC009 · Hug Hairy Monster T-Shirt · Light Blue
```

🔴 **아무 버튼도 더 누르지 않는다.** 특히 **「🔄 다시 분석」을 누르지 않는다** —
이번 확인의 질문이 「셀러가 아무것도 안 눌러도 보이는가」이기 때문이다.
🟡 분석에는 시간이 걸린다. 화면이 「가격 확인 중」류 표시를 하면 **기다린다**.

## 4. 판정 기준 — **CPO 가 적용한다** (CEO 는 읽지 않아도 된다)

> 🔴 §3 의 ○/✕ 를 아래에 대입한다. **CEO 가 판정을 내리지 않는다.**

### 🟢 GO

```
A1·A2·A3        전부 ○
B1~B3           **최소 2곳 이상** ○      ← 3/3 이 이상적이나 검색 변동이 있다(SP-10)
B4              ○
C1 또는 C2      **최소 하나** ○          ← 국내·해외 둘 다 있으면 더 좋다
C3              ○
E1~E5           전부 ✕(= 보이지 않음)
```

### 🟡 HOLD

```
A 전부 ○ 이고 B1~B3 중 **1곳만** 뜨는 경우          ⟹ 노출 축 재확인
A·B 는 ○ 인데 **C 가 전부 ✕**                      ⟹ 가격/MI 연결 누락
E1~E4 중 하나라도 ○(내부 토큰 노출)                 ⟹ 표시 계약 위반 · 수정 범위 좁다
E5 ○ (화면 깨짐)                                   ⟹ 원인 지점만 보고
```

### 🔴 NO-GO

```
B1~B3 가 **전부 ✕** 이고 다른 후보도 0(B5 = 0곳)     ⟹ 검색 결과가 화면에 연결되지 않는다
A2 또는 A3 가 ✕ — 즉 **버튼을 눌러야만** 보인다       ⟹ 「셀러가 아무것도 안 눌러도」가 깨진다
정상 동작을 위해 Search/Identity/MI 구조를 다시 뜯어야 하는 경우
```

### 🔴🔴 판정에서 **제외** 하는 것 (실패로 세지 않는다)

```
① **기존 상품을 열어서** 후보가 없었다       → §1 위반. 다시 「새 상품 분석」으로 한다
② 확인 중 **F5 를 눌러서** 후보가 사라졌다   → 같은 이유(일시 값 설계)
③ 세 판매처 중 하나가 **이번엔 안 떴다**     → 검색 결과는 실행마다 달라진다(SP-10 실측:
   같은 질의의 URL 겹침 3~30%) ⟹ **2/3 이면 GO 범위** 다
④ 국내가 안 보인다                          → 그 상품의 국내 유통 자체가 변수다(SP-10/11)
⑤ `PRESUMED_SAME` 이 `SAME` 이 아니다        → **화면에 안 보이는 내부 등급** 이고
   CPO 가 「등급 변경 금지」로 닫아 둔 축이다. 이 확인의 대상이 아니다
```

## 5. CTO 가 **미리** 확인한 것 (화면 앞까지)

```
🟢 Production 살아 있다          /  200 · /pipeline 307(로그인) · /today 307 — 배포 `57542a83`
🟢 자동 1회차가 Search 를 켠다    `check/route.ts` 가 `webSearch: true` 를 넘긴다(계약으로 잠금)
🟢 그 호출이 **자동으로** 일어난다 `pipeline/page.tsx` 의 최초 스냅샷 블록이 POST /check 한다
🟢 응답을 **버리지 않는다**        WU-082 가 고친 자리 — `autoCheckResult` 로 패널에 내려간다
🟢 후보가 화면 칸까지 간다         `webSearchEvidence` → `transientEvidence` →
                                 `computeMarketIntelligence`(SP-07 배선 · 계약으로 잠금)
🟢 상품당 Search **1회**          `MAX_SEARCHES_PER_PRODUCT = 1` · retry/fallback **0**(계약)
🟢 E2E 실측(운영 함수)            Search 1회 → 9 URL → 후보 3 → tier COMPARISON ×3 ·🇰🇷1 ·🌎1
🔴 **픽셀은 확인하지 못했다**      ⟹ §3 이 필요한 이유
```

🔴 이번 작업에서 **운영 코드를 한 줄도 바꾸지 않았다** — Search/Identity/MI/threshold/
`PRESUMED_SAME`/`crossSellerReserved`/Evidence/Crawl/Registry/1-hop **전부 0**.
