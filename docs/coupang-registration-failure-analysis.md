# 쿠팡 등록 실패 원인 분석 (Epic 1)

> 실측 운영 카운트(발생 횟수)는 아직 없다 — 이 제품은 아직 실사용 트래픽이 쌓이지
> 않았고, 이번 세션 이전까지는 실패를 구조화해서 기록하는 수단(ErrorCode/Trace ID)
> 자체가 없었다. 대신 코드 전체를 읽어 "이 경로가 실제로 어떤 조건에서 실패하는가"를
> 원인별로 전수 분류했다. 이번 Sprint에서 추가한 ErrorCode(Epic 2)와 Trace ID(Epic 5)가
> 쌓이기 시작하면 이 문서를 실측 카운트로 교체할 수 있다.

## 분류 기준

- **원인**: 코드 상에서 이 실패가 발생하는 정확한 조건.
- **자동 해결 가능**: 재시도만으로 해결될 수 있으면 예(Epic 6 대상). 사용자가
  데이터/설정을 고쳐야 하면 아니오.
- **ErrorCode**: 이번 Sprint에서 부여한 코드(`packages/shared/src/error-codes.ts`).

## 1. 이미지

| 원인 | ErrorCode | 자동 해결 가능 | 비고 |
|---|---|---|---|
| 상품 페이지에서 이미지 후보를 하나도 못 찾음(사이트 자체에 이미지가 없거나 Cloudflare 등 봇 차단으로 페이지 자체를 못 받음) | IMG001 | 아니오 | Shopify는 이번 Sprint 이전 미션에서 Playwright 우회(JSON 우선 전략)로 상당 부분 해결됨. 비-Shopify 사이트에서 Cloudflare/봇 차단이 걸리면 여전히 재현 가능 — SiteStrategy를 다른 플랫폼으로 확장하는 것이 근본 해결책(다음 Sprint 범위 아님) |
| 이미지 다운로드 자체 실패(네트워크 오류/타임아웃/CDN 일시 오류) | IMG002 | **예** | 이번 Sprint에서 `downloader.service.ts`에 3회 재시도(지수 백오프) 추가 완료 |
| JPG 변환 실패(원본이 손상됐거나 지원 안 하는 포맷) | IMG003 | 아니오 | 원본 파일 자체 문제 — 재시도해도 동일하게 실패 |
| 대표 이미지 미지정 | IMG004 | 아니오 | 사용자가 이미지 카드에서 대표 이미지를 선택해야 함 |
| 이미지 개수가 플랫폼 한도(쿠팡 10장) 초과 | IMG005 | 아니오(자동 절단으로 처리됨) | `MAX_ADDITIONAL_IMAGES` 어댑터 레벨에서 이미 자동으로 잘라서 등록 — 실패가 아니라 확인 모달에서 안내만 함 |

## 4. 쿠팡 등록(비즈니스 데이터 누락)

`missingSellerConfigFields()`(register/route.ts)가 한 번에 여러 항목을 검사하는데,
실제로는 대부분 "판매자 설정을 아직 한 번도 안 채웠다"는 단일 원인에서 여러 필드가
동시에 비어 있는 형태로 나타난다.

| 원인 | ErrorCode | 자동 해결 가능 | 비고 |
|---|---|---|---|
| 카테고리 미확정(추천만 뜨고 선택 안 함, 또는 검증된 코드 없음) | CP001 | 아니오 | 사용자가 카테고리 추천/검색에서 확정해야 함 |
| 택배사/출고지 미설정 | CP002 | 아니오 | 설정 페이지에서 1회만 채우면 이후 재발 안 함 |
| 반품지 미설정(반품지명/연락처/우편번호/주소 포함) | CP003 | 아니오 | 위와 동일 |
| 필수 옵션 누락(옵션 값 자체가 없음) | CP004 | 아니오 | 원본 사이트에 옵션 정보가 없으면 구조적으로 못 채움 — WARNING으로만 처리하고 등록은 막지 않음(현재 어댑터 정책) |
| 대표 이미지 없음 | CP006(이미지 형식 포함) | 아니오 | Epic 1의 IMG004와 겹치는 원인 — 진입 지점만 다름(클라이언트 검증 vs 서버 검증) |
| 상품명/브랜드/판매가 등 일반 필수값 누락 | CP005 | 아니오 | 브랜드는 쿠팡이 스마트스토어보다 엄격하게 요구(ERROR) — `coupang.adapter.ts` 참고 |

## 5. API(기술적 실패)

| 원인 | ErrorCode | 자동 해결 가능 | 비고 |
|---|---|---|---|
| 쿠팡 인증 정보 자체가 없음(Access/Secret/Vendor ID 미설정) | API001 | 아니오 | 설정 페이지에서 1회 입력하면 재발 안 함 |
| 쿠팡이 인증 정보를 거부(401/403 — 오타/만료/권한 문제) | API002 | 아니오 | 키를 다시 확인해야 함 — 재시도로 해결 안 됨 |
| 네트워크 연결 실패(fetch 자체가 throw — DNS/타임아웃/프록시 오류) | API003 | **예** | 이번 Sprint에서 `callCoupangApi` 호출에 재시도 래퍼(`withRetry`) 적용 완료 |
| 쿠팡 API가 429/5xx로 응답(일시적 서버 과부하/Rate Limit) | API004 | **예** | 동일하게 `withRetry`가 429/5xx만 최대 3회 재시도 |
| 쿠팡 API가 4xx로 요청 자체를 거부(카테고리 코드 오류, 필수 attributes 누락 등 — 쿠팡 응답 메시지 그대로) | API005 | 아니오 | 쿠팡이 반환한 메시지를 그대로 사용자에게 보여줌 — attributes/notices를 실제로 채우지 않고 있는 게 근본 원인(별도 백로그, 카테고리 메타정보 조회 API 미연동) |

## 요약 — 무엇이 "자동 해결 가능"인가

이번 Sprint(Epic 6)에서 자동 재시도를 붙인 건 딱 두 곳, **네트워크/타임아웃/429/5xx**뿐이다.
나머지(카테고리/배송/반품/옵션/이미지 형식/인증 정보 자체 없음)는 전부 사용자가
직접 채워야 하는 데이터/설정 문제라 재시도로는 절대 해결되지 않는다 — 그래서
Epic 2의 ErrorCode에 `autoRetryable` 플래그를 명시적으로 박아뒀고, Epic 3 문의하기와
Epic 4 Registration Report 둘 다 이 플래그를 그대로 사용자에게 보여준다.
